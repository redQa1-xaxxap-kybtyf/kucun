# 列表页面加载方式分析报告

## 执行摘要

本报告分析了销售订单、厂家发货、退货订单三个列表页面的数据加载实现，评估其是否遵循 Next.js 15 + React Query v5 最佳实践，并识别潜在问题。

**关键发现：**

- ✅ 销售订单：完全符合最佳实践
- ⚠️ 厂家发货：使用 prefetchQuery，存在潜在问题
- ❌ 退货订单：缺少服务端数据预取，存在严重性能问题

---

## 1. 销售订单列表页面

### 📄 文件位置

- Server Component: `app/(dashboard)/sales-orders/page.tsx`
- Client Component: `app/(dashboard)/sales-orders/page-client.tsx`
- List Component: `components/sales-orders/erp-sales-order-list.tsx`

### ✅ 实现分析

#### Route Segment Config

```typescript
export const dynamic = 'force-dynamic';
export const fetchCache = 'force-no-store';
export const runtime = 'nodejs';
export const revalidate = 0;
```

✅ **正确**：明确禁用缓存，确保每次请求都获取最新数据

#### Server Component 数据获取

```typescript
const queryClient = new QueryClient();
const initialData = await getSalesOrders(queryParams);

queryClient.setQueryData(salesOrderQueryKeys.list(queryParams), {
  data: initialData.data,
  pagination: initialData.pagination,
});
```

✅ **正确**：使用 `setQueryData` 直接设置缓存数据

#### HydrationBoundary 使用

```typescript
<HydrationBoundary state={dehydrate(queryClient)}>
  <SalesOrdersPageClient initialParams={queryParams} />
</HydrationBoundary>
```

✅ **正确**：通过 HydrationBoundary 传递服务端预取的数据

#### Client Component 查询配置

```typescript
const { data, isLoading, error, isFetching } = useQuery({
  queryKey: salesOrderQueryKeys.list(queryParams),
  queryFn: () => getSalesOrders(queryParams),
  staleTime: 30 * 1000,
  refetchOnWindowFocus: false,
  placeholderData: previousData => previousData,
  refetchOnMount: false,
  gcTime: 10 * 60 * 1000,
});
```

✅ **优秀**：

- `staleTime: 30s` - 减少不必要的重新获取
- `placeholderData` - 保持上一次数据，避免闪烁
- `refetchOnMount: false` - 避免重复请求
- `gcTime: 10min` - 长缓存时间，优化后退/前进体验

### 🎯 评分：10/10

完全符合 Next.js 15 + React Query v5 最佳实践

## 2. 厂家发货列表页面

### 📄 文件位置

- Server Component: `app/(dashboard)/factory-shipments/page.tsx`
- Client Component: `app/(dashboard)/factory-shipments/page-client.tsx`

### ⚠️ 实现分析

#### Route Segment Config

```typescript
export const dynamic = 'force-dynamic';
export const fetchCache = 'force-no-store';
export const runtime = 'nodejs';
export const revalidate = 0;
```

✅ **正确**：配置正确

#### Server Component 数据预取

```typescript
const queryClient = new QueryClient();

await queryClient.prefetchQuery({
  queryKey: factoryShipmentQueryKeys.list(queryParams),
  queryFn: () => getFactoryShipmentOrdersServer(queryParams),
});

return (
  <HydrationBoundary state={dehydrate(queryClient)}>
    <FactoryShipmentsPageClient initialParams={queryParams} />
  </HydrationBoundary>
);
```

### 🔴 潜在问题

#### 问题 1: 使用 prefetchQuery 而非 setQueryData

**影响**: 中等
**描述**:

- `prefetchQuery` 会在服务端和客户端各执行一次查询函数
- 可能导致重复的数据库查询
- 相比 `setQueryData` 效率较低

**推荐修复**:

```typescript
// ❌ 当前实现
await queryClient.prefetchQuery({
  queryKey: factoryShipmentQueryKeys.list(queryParams),
  queryFn: () => getFactoryShipmentOrdersServer(queryParams),
});

// ✅ 推荐实现
const initialData = await getFactoryShipmentOrdersServer(queryParams);
queryClient.setQueryData(factoryShipmentQueryKeys.list(queryParams), {
  data: initialData.data,
  pagination: initialData.pagination,
});
```

#### 问题 2: 日期参数类型转换

```typescript
const startDate = params.startDate
  ? new Date(params.startDate as string)
  : undefined;
const endDate = params.endDate ? new Date(params.endDate as string) : undefined;
```

⚠️ **问题**:

- 将字符串转换为 Date 对象可能导致序列化问题
- Date 对象在 JSON 序列化时会转换为 ISO 字符串
- 可能与客户端期望的格式不一致

**推荐**: 保持字符串格式

```typescript
const startDate = (params.startDate as string) || undefined;
const endDate = (params.endDate as string) || undefined;
```

### 🎯 评分：7/10

基本符合最佳实践，但存在可优化的地方

### 📄 文件位置

- Server Component: `app/(dashboard)/return-orders/page.tsx`
- Client Component: `app/(dashboard)/return-orders/page-client.tsx`
- List Component: `components/return-orders/erp-return-order-list.tsx`

### ❌ 实现分析

#### Route Segment Config

```typescript
export const dynamic = 'force-dynamic';
export const fetchCache = 'force-no-store';
export const runtime = 'nodejs';
export const revalidate = 0;
```

✅ **正确**：配置正确

#### Server Component - 缺少数据预取

```typescript
export default async function ReturnOrdersPage({ searchParams }: PageProps) {
  const params = await searchParams;
  const initialParams = {
    page: params?.page ? parseInt(params.page, 10) : 1,
    limit: params?.limit ? parseInt(params.limit, 10) : 20,
    search: params?.search || '',
    // ... 其他参数
  };

  return <ReturnOrdersPageClient initialParams={initialParams} />;
}
```

### 🔴 严重问题

#### 问题 1: 缺少服务端数据预取

**影响**: 严重
**描述**:

- Server Component 没有预取数据
- 没有使用 HydrationBoundary
- 数据完全在客户端获取
- 失去了 SSR 的性能优势

**后果**:

1. **首屏加载慢**: 用户需要等待 JavaScript 加载 + 数据请求
2. **SEO 差**: 搜索引擎无法索引列表数据
3. **瀑布式请求**: HTML → JS → 数据（串行）
4. **CLS 问题**: 布局偏移，用户体验差

#### 问题 2: 客户端使用 fetch 而非 API 函数

```typescript
// ❌ 当前实现
const { data, isLoading } = useQuery({
  queryKey: queryKeys.returnOrders.list(queryParams),
  queryFn: async () => {
    const response = await fetch(
      `/api/return-orders?${new URLSearchParams(...)}`
    );
    if (!response.ok) {
      throw new Error(`获取退货订单列表失败: ${response.statusText}`);
    }
    return response.json();
  },
  staleTime: 5 * 60 * 1000,
  refetchOnWindowFocus: false,
});
```

**问题**:

- 直接使用 fetch 而非封装的 API 函数
- 不一致的数据获取模式
- 缺少类型安全
- 错误处理不统一

#### 问题 3: Mock 数据回退机制

```typescript
const mockData = {
  success: true,
  data: {
    returnOrders: [],
    pagination: { page: 1, limit: 20, total: 0, totalPages: 1 },
  },
};

const displayData = error ? mockData : queryData;
```

⚠️ **问题**:

- 错误时静默失败，返回空数据
- 用户无法区分"无数据"和"加载失败"
- 应该向用户显示错误信息

#### 问题 4: 内部状态管理冗余

```typescript
const [queryParams, setQueryParams] = useState<ReturnOrderQueryParams>(
  initialParams || { ... }
);
```

⚠️ **问题**:

- 维护内部 queryParams 状态
- 与 initialParams 可能不同步
- 应该直接使用 initialParams（单一数据源）

### 🎯 评分：3/10

缺少关键的服务端预取功能，性能和用户体验较差

## 修复建议

### 修复 1: 退货订单添加服务端预取

**文件**: `app/(dashboard)/return-orders/page.tsx`

```typescript
import {
  dehydrate,
  HydrationBoundary,
  QueryClient,
} from '@tanstack/react-query';

import { getReturnOrders } from '@/lib/api/return-orders';
import { queryKeys } from '@/lib/queryKeys';

export default async function ReturnOrdersPage({ searchParams }: PageProps) {
  const params = await searchParams;
  const initialParams = {
    page: params?.page ? parseInt(params.page, 10) : 1,
    limit: params?.limit ? parseInt(params.limit, 10) : 20,
    search: params?.search || '',
    status: isReturnOrderStatus(params?.status) ? params?.status : undefined,
    sortBy: params?.sortBy || 'createdAt',
    sortOrder: (params?.sortOrder as 'asc' | 'desc') || 'desc',
    startDate: params?.startDate || undefined,
    endDate: params?.endDate || undefined,
  };

  // ✅ 创建 QueryClient
  const queryClient = new QueryClient();

  // ✅ 服务端获取数据
  const initialData = await getReturnOrders(initialParams);

  // ✅ 预填充缓存
  queryClient.setQueryData(
    queryKeys.returnOrders.list(initialParams),
    {
      data: initialData.data,
      pagination: initialData.pagination,
    }
  );

  return (
    // ✅ 使用 HydrationBoundary
    <HydrationBoundary state={dehydrate(queryClient)}>
      <ReturnOrdersPageClient initialParams={initialParams} />
    </HydrationBoundary>
  );
}
```
