# 采购订单供应商字段优化方案

**分析日期**: 2025-01-11
**问题**: 订单级supplierId和明细级supplierId造成混淆,产品来源判断不清晰

---

## 🔴 当前问题分析

### 问题1: 语义混淆

```typescript
PurchaseOrder {
  supplierId: "供应商A"  // 主供应商
  items: [
    { supplierId: "供应商A" },  // 实际供应商
    { supplierId: "供应商B" },  // 实际供应商
    { supplierId: "供应商C" }   // 实际供应商
  ]
}
```

**核心问题**:

- ❌ 当订单级supplierId = "供应商A",但明细中有"供应商B"和"C"时,**产品到底是谁提供的?**
- ❌ 是看订单级还是明细级?两者不一致时以谁为准?
- ❌ 用户在查询"供应商A的采购记录"时,应该包含这个订单吗?
- ❌ 成本归属、应付账款、供应商绩效评估该看哪个字段?

### 问题2: 业务逻辑矛盾

**场景**: 一个采购订单包含3个产品,来自3个不同供应商

```
订单编号: PO-2025-001
订单级供应商: 供应商A (主供应商?)

明细:
1. 产品001 - 供应商A - 1000元
2. 产品002 - 供应商B - 2000元
3. 产品003 - 供应商C - 3000元
```

**问题**:

1. 为什么要有"主供应商"的概念?实际上每个产品都是独立供应的
2. 订单级的运费、报关费等费用应该归属给谁?
3. 如果供应商A只提供了1000元的货,凭什么称它为"主"供应商?
4. 应付账款记录时,是记录给"订单主供应商"还是各个明细供应商?

### 问题3: 数据一致性风险

**自动填充逻辑**:

```typescript
// 当订单供应商改变时,自动填充到明细
useEffect(() => {
  if (supplierIdValue) {
    items.forEach((item, index) => {
      if (!item.supplierId) {
        form.setValue(`items.${index}.supplierId`, supplierIdValue);
      }

```

**风险**:

- ⚠️ 用户选择"供应商A"作为订单供应商
- ⚠️ 系统自动填充到所有明细
- ⚠️ 用户修改某个明细的供应商为"供应商B"
- ⚠️ 现在订单级显示"供应商A",但实际有明细是"供应商B"
- ❌ **数据不一致,语义混乱**

## ✅ 正确的方案:移除订单级supplierId

### 方案核心理念

> **采购订单只是一个容器,真正的供应关系在明细级别**

**原则**:

1. ✅ 每个产品明确知道是谁供应的(明细级supplierId)
2. ✅ 成本、应付账款、供应商绩效都基于明细级数据
3. ✅ 不需要"主供应商"的模糊概念
4. ✅ 支持真正的多供应商混合采购

### 数据库Schema调整

```prisma
model PurchaseOrder {
  id              String  @id @default(uuid())
  orderNumber     String  @unique
  // ❌ supplierId      String  @map("supplier_id")  // 删除!
  containerNumber String?
  userId          String
  status          String
  // ...

  items          PurchaseOrderItem[]

  // ❌ 移除订单级supplier关系

model PurchaseOrderItem {
  id              String  @id @default(uuid())

  productId       String?

  // ...

  // ✅ 明细关联供应商
  supplier        Supplier @relation(fields: [supplierId], references: [id])
}
```

### 订单列表显示逻辑

```typescript
function getSupplierDisplay(order: PurchaseOrder) {
  // 统计订单中所有唯一供应商
  const supplierMap = new Map<string, { name: string; amount: number }>();

  order.items.forEach(item => {
    const existing = supplierMap.get(item.supplierId);
    if (existing) {
      existing.amount += item.totalPrice;
    } else {
      supplierMap.set(item.supplierId, {
        name: item.supplier.name,
        amount: item.totalPrice,
      });
    }
  });

  if (supplierMap.size === 1) {
    // 单供应商
    return supplierMap.values().next().value.name;
  } else {
    // 多供应商 - 显示主要的2个
    const sorted = Array.from(supplierMap.values()).sort(
      (a, b) => b.amount - a.amount
    );

    if (sorted.length === 2) {
      return `${sorted[0].name}、${sorted[1].name}`;
    } else {
      return `${sorted[0].name}、${sorted[1].name} +${sorted.length - 2}个`;
    }
  }
}
```

### 第一阶段:数据库迁移

```bash
# 1. 创建迁移脚本
npx prisma migrate dev --name remove_purchase_order_supplier_id --create-only

# 2. 编辑迁移SQL,添加数据处理逻辑
# migration.sql:
-- 1. 检查数据一致性(确保没有孤立的订单级supplierId)
SELECT po.id, po.supplierId as order_supplier,
       GROUP_CONCAT(DISTINCT poi.supplierId) as item_suppliers
FROM purchase_orders po
LEFT JOIN purchase_order_items poi ON po.id = poi.purchaseOrderId
GROUP BY po.id
HAVING order_supplier NOT IN (item_suppliers);

-- 2. 移除外键约束
ALTER TABLE `purchase_orders` DROP FOREIGN KEY `purchase_orders_supplierId_fkey`;

-- 3. 移除字段
ALTER TABLE `purchase_orders` DROP COLUMN `supplier_id`;

-- 4. 移除索引
ALTER TABLE `purchase_orders` DROP INDEX `idx_purchase_orders_supplier`;

# 3. 运行迁移
npx prisma migrate dev
```

## 🎯 最终建议

### ⭐ 强烈建议:移除订单级supplierId

**理由**:

1. ✅ **语义清晰**: 产品来源明确,不存在歧义
2. ✅ **数据一致**: 单一数据源,无一致性问题
3. ✅ **业务准确**: 成本、应付、绩效评估都基于真实供应关系
4. ✅ **真正的多供应商**: 不需要"主"供应商的概念
5. ✅ **可优化体验**: 通过批量设置、默认供应商等功能优化输入

**用户体验优化**:

1. 产品默认供应商自动填充
2. 批量设置供应商功能
3. 按供应商分组视图
4. "使用上一行供应商"快捷按钮

## 📝 你的担心是完全正确的

你提到的问题击中要害:

> "为什么我要保留主供应商,那产品的来源怎么判断?"

**答案**: 确实无法判断!保留订单级supplierId是一个**设计错误**,会造成:

- ❌ 产品来源不清晰
- ❌ 需要业务人员记住"以明细为准"的规则
- ❌ 数据可能不一致
- ❌ 查询时需要特殊处理

**正确做法**:

- ✅ 移除订单级supplierId
- ✅ 只保留明细级supplierId
- ✅ 产品来源=明细的supplierId,清晰明确
- ✅ 通过UI优化解决用户体验问题

---

**结论**: 建议移除PurchaseOrder.supplierId,只保留PurchaseOrderItem.supplierId
