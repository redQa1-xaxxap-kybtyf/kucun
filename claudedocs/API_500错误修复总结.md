# API 500错误修复总结

## 问题分析

### 错误现象
在创建厂家发货订单页面加载时，浏览器控制台出现两个500错误：
- 错误类型：Failed to load resource: the server responded with a status of 500 (Internal Server Error)
- Prisma错误：`Invalid prisma.product.count() invocation: { select: { _count...`

### 根本原因分析

经过详细代码审查，发现以下关键信息：

1. **Prisma查询约束**
   - `prisma.count()`方法只接受`where`参数
   - 不能传递`select`或`_count`参数给`count()`方法
   - 错误信息表明有代码尝试向`count()`传递了`select`参数

2. **可能的触发场景**
   - 仪表盘页面加载时的统计查询
   - 产品列表API的count查询
   - 客户选择器的搜索查询

3. **代码审查结果**
   经过全面检查，所有显式的`count()`调用都是正确的：
   - `lib/api/handlers/products-list.ts:163`: `prisma.product.count({ where })` ✅
   - `app/api/dashboard/overview/route.ts`: 所有count调用格式正确 ✅

### 可能的隐藏问题

虽然显式代码都正确，但500错误可能来自：

1. **数据库状态问题**
   - 数据库表结构与Prisma schema不匹配
   - 缺少必要的索引或约束
   - 数据完整性问题

2. **缓存或编译问题**
   - Prisma客户端未重新生成
   - Next.js缓存问题
   - TypeScript编译缓存

3. **并发查询问题**
   - 多个查询并发执行导致的竞态条件
   - 数据库连接池问题

```typescript
export async function queryProducts(params: {
  where: Prisma.ProductWhereInput;
  select: ReturnType<typeof buildProductSelect>;
  sortBy: string;
  sortOrder: string;
  page: number;
  limit: number;
}) {
  const { where, select, sortBy, sortOrder, page, limit } = params;

  try {
    return await Promise.all([
      prisma.product.findMany({
        where,
        select,
        orderBy: { [sortBy]: sortOrder },
        skip: (page - 1) * limit,
        take: limit,
      }),
      prisma.product.count({ where }), // 确保只传where参数
    ]);
  } catch (error) {
    console.error('Product query failed:', {
      error,
      where,
      hasSelect: !!select,
      sortBy,
      sortOrder,
      page,
      limit
    });
    throw error;
  }
}
```

```typescript
export function withErrorLogging<T>(
  handler: () => Promise<T>
): Promise<T> {
  return handler().catch((error) => {
    console.error('[API Error]', {
      message: error.message,
      stack: error.stack,
      code: error.code,
      meta: error.meta,
    });
    throw error;
  });
}
```
