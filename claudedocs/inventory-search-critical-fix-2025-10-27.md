# 库存搜索关键Bug修复总结

## 修复日期

2025-10-27

## 问题描述

用户报告了一个**非常严重**的搜索输入bug:

1. **输入被删除**: 在搜索框输入"360"后,继续输入任何数字都会被立即删除,只保留"360"
2. **清空失败**: 尝试清空"360"时,内容会重复出现,需要等待一段时间才消失
3. **用户体验极差**: 完全无法正常使用搜索功能

## 根本原因分析

### 问题代码

```typescript
// ❌ 错误的URL同步逻辑
React.useEffect(() => {
  const urlSearch = params.search || '';
  if (urlSearch !== searchInput) {
    setSearchInput(urlSearch); // 在防抖期间会覆盖用户输入!
  }
}, [params.search]);
```

### 问题场景重现

```
时间线:
t=0ms:   用户输入"360"
         → searchInput = "360"
         → 启动300ms防抖定时器

t=50ms:  用户继续输入"1"
         → searchInput = "3601"
         → 清除旧定时器,启动新的300ms定时器

t=100ms: params.search 仍然是 "" (URL还没更新)
         → URL同步effect触发
         → 检查: "" !== "3601" → true
         → 执行: setSearchInput("")
         → ❌ 用户看到输入被清空!

t=150ms: 用户再次输入"360"
         → searchInput = "360"
         → 启动300ms定时器

t=450ms: 定时器到期,更新URL
         → params.search = "360"
         → URL同步effect触发
         → 检查: "360" !== "360" → false
         → 不执行同步

t=500ms: 用户输入"1"
         → searchInput = "3601"

t=600ms: params.search 仍然是 "360"
         → URL同步effect触发
         → 检查: "360" !== "3601" → true
         → 执行: setSearchInput("360")
         → ❌ 用户输入的"1"被删除了!
```

### 核心问题

**URL同步effect与本地状态更新产生竞态条件**:

1. 用户快速输入时,本地状态(`searchInput`)立即更新
2. URL更新被300ms防抖延迟
3. 在防抖等待期间,URL同步effect错误地将旧的URL值同步回本地状态
4. 导致用户输入被覆盖

## 修复方案

### 核心思路

**只在用户没有正在输入时才同步URL到本地状态**

判断标准: 检查`searchTimerRef.current`是否为null

- 如果有pending的定时器 → 用户正在输入 → **不要同步**
- 如果没有pending的定时器 → 用户已停止输入 → **可以安全同步**

### 修复代码

```typescript
// ✅ 正确的URL同步逻辑
React.useEffect(() => {
  const urlSearch = params.search || '';

  // 如果有pending的防抖定时器，说明用户正在输入，不要覆盖
  if (searchTimerRef.current) {
    return;
  }

  // 只在URL变化且与本地状态不同时才同步
  if (urlSearch !== searchInput) {
    setSearchInput(urlSearch);
  }
}, [params.search]);
```

### 修复后的时间线

```
时间线:
t=0ms:   用户输入"360"
         → searchInput = "360"
         → searchTimerRef.current = <Timer ID>

t=50ms:  用户继续输入"1"
         → searchInput = "3601"
         → 清除旧定时器
         → searchTimerRef.current = <New Timer ID>

t=100ms: params.search 仍然是 ""
         → URL同步effect触发
         → 检查: searchTimerRef.current !== null
         → ✅ 直接return,不执行同步
         → ✅ 用户输入"3601"保持不变!

t=350ms: 定时器到期,更新URL
         → updateParams({ search: "3601" })
         → searchTimerRef.current = null (已清除)
         → params.search = "3601"

t=360ms: URL同步effect触发
         → 检查: searchTimerRef.current === null
         → 检查: "3601" !== "3601" → false
         → 不执行同步
         → ✅ 一切正常!
```

## 技术债务清理

### 解决的问题

1. ✅ **竞态条件消除**: URL同步不再与用户输入产生冲突
2. ✅ **状态一致性**: 本地状态和URL状态的同步逻辑更加健壮
3. ✅ **用户体验**: 搜索输入变得流畅自然

### 遵循的原则

1. **KISS原则**: 用简单的定时器检查解决复杂的竞态问题
2. **防御性编程**: 在同步前检查用户操作状态
3. **最小侵入**: 只修改必要的逻辑,不改变整体架构
