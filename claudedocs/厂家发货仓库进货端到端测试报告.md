## 业务流程分析

### 1. 厂家发货仓库进货业务流程

```
1. 创建厂家发货订单
   ├─ 选择客户
   ├─ 添加产品明细（含归属：客户/自用）
   ├─ 设置金额信息
   └─ 提交订单

2. 自用货物入库流程
   ├─ 打开订单详情
   ├─ 点击"确认自用货入库"
   ├─ 填写入库信息
   │  ├─ 入库数量
   │  ├─ 每单位片数
   │  ├─ 批次号（可选）
   │  ├─ 库位（可选）
   │  └─ 备注（可选）
   └─ 确认入库
      ├─ 创建入库记录（Inbound）
      └─ 更新明细状态（selfInboundStatus: 'received'）
```

### 2. 核心API分析

#### 2.1 入库API (`/api/factory-shipments/[id]/inbound`)

**文件位置**: `E:\kucun\app\api\factory-shipments\[id]\inbound\route.ts`

**功能**:
- 标记自用补货明细为已入库
- 验证明细归属（只能是自用货）
- 更新入库状态和时间戳

**核心逻辑**:
```typescript
// 1. 验证明细必须是自用货
const invalidItems = items.filter(
  item => item.ownership !== FACTORY_SHIPMENT_ITEM_OWNERSHIP.SELF
);

// 2. 批量更新入库状态
await prisma.factoryShipmentOrderItem.updateMany({
  where: { id: { in: items.map(item => item.id) } },
  data: {
    selfInboundStatus: 'received',
    inboundReceivedAt: new Date(),
  },
});
```

#### 2.2 确认入库对话框

**文件位置**: `E:\kucun\components\factory-shipments\confirm-inbound-dialog.tsx`

**功能**:
- 筛选待入库的自用明细
- 区分有产品ID和无产品ID的明细
- 为有产品ID的明细创建入库记录
- 调用API更新明细状态

**数据流**:
```typescript
// 1. 筛选自用待入库明细
```
