## ⚠️ 发现的问题和限制

### 1. 认证系统要求 🔒

**现象**:

- 访问 `/inventory/inbound/create` 重定向到登录页 `/auth/signin`
- API调用返回 `401 Unauthorized` 或 `{"success": false, "error": "未授权访问"}`
- 产品搜索下拉框显示"未找到相关产品"（实际是认证失败）

**原因分析**:

```typescript
// 所有入库相关页面和API都需要认证
middleware.ts → 检查session
  ↓
session不存在
  ↓
redirect → /auth/signin
```

**影响**:

- ✅ **这是正确的行为**: 系统安全性设计正确
- ⚠️ 限制了自动化UI测试的执行
- ⚠️ 需要在测试中实现登录流程

**解决方案**:

1. **推荐方案**: 在测试中实现完整登录流程

   ```typescript
   test.beforeAll(async ({ page }) => {
     // 登录步骤
     await page.goto('/auth/signin');
     await page.fill('[name="username"]', 'admin');
     await page.fill('[name="password"]', 'admin123456');
     // 处理验证码
     await page.fill('[name="captcha"]', 'TEST1234');
     await page.click('button[type="submit"]');
     await page.waitForURL('/dashboard');
   });
   ```

2. **替代方案**: 使用storageState保存登录状态

   ```typescript
   // 一次性登录，保存状态
   npx playwright codegen --save-storage=auth.json

   // 在测试中使用
   test.use({ storageState: 'auth.json' });
   ```

3. **开发环境方案**: 添加测试环境认证绕过
   ```typescript
   if (process.env.E2E_TEST_MODE === 'true') {
     // 跳过认证检查
   }
   ```

### 2. 验证码机制 🔐

**现象**:
登录页面要求输入验证码，测试代码使用固定值 `TEST1234` 失败

**分析**:

```typescript
// lib/services/captcha-service.ts
const isTestBypass =
  (process.env.NODE_ENV === 'test' || process.env.NODE_ENV === 'development') &&
  captcha.toUpperCase() === 'TEST1234';
```

**问题**:

- Playwright测试运行时，`NODE_ENV` 可能不是 'test' 或 'development'
- 验证码服务可能使用了不同的环境变量

**建议**:

1. 在playwright.config.ts中设置环境变量:

   ```typescript
   use: {
     env: {
       NODE_ENV: 'development',
       E2E_TEST: 'true'
     }
   }
   ```

2. 或者使用图像识别处理真实验证码（更复杂）
