# 厂家发货确认问题快速诊断指南

## 🚀 快速开始

### 1. 重启开发服务器

```bash
# 停止当前服务器 (Ctrl+C)
# 重新启动
npm run dev
```

### 2. 打开浏览器控制台

- 按 **F12** 打开开发者工具
- 切换到 **Console** 标签

### 3. 尝试确认发货

1. 登录系统
2. 导航到 **厂家发货** 模块
3. 打开任意一个订单详情页
4. 点击 **"确认发货"** 按钮
5. 填写集装箱号码（例如: `ABCD1234567`）
6. 可选填写船运公司（例如: `中远海运`）
7. 点击 **"确认发货"** 提交

### 4. 查看日志

## 🔍 常见问题诊断

### 问题 1: 集装箱号码验证失败

**错误信息**:

```
数据验证失败: 集装箱号码不能超过50个字符
```

**原因**: 输入的集装箱号码太长

**解决方案**:

- 检查输入的集装箱号码长度
- 确保不超过 50 个字符

---

### 问题 2: 日期格式错误

**错误信息**:

```
数据验证失败: Invalid datetime string! Must be UTC.
```

**原因**: 日期字段不是有效的 ISO 8601 格式

**调试**: 查看浏览器控制台的 `[DEBUG] 确认发货 - 发送到服务器的数据` 日志，检查 `shipmentDate` 字段

**示例**:

```json
{
  "shipmentDate": "2025-01-13T10:30:00.000Z"  // ✅ 正确
  "shipmentDate": "2025-01-13"                // ❌ 错误
  "shipmentDate": null                        // ❌ 错误
}
```

---

### 问题 3: 状态流转失败

**错误信息**:

```
状态流转失败: 订单状态不能从 X 变更为 shipped
```

**原因**: 当前订单状态不允许直接变更为"已发货"

**调试**:

1. 查看订单当前状态
2. 检查是否启用了智能状态流转

**解决方案**:

- 智能状态流转已启用，应该自动处理
- 如果仍然失败，可能是订单状态异常

**检查代码**:

- `lib/api/handlers/factory-shipment-status.ts` 第 29-54 行（状态流转规则）

---

### 问题 4: 集装箱号码为空

**错误信息**:

```
必须填写集装箱号才能标记为已发货
```

**原因**: `containerNumber` 字段为空或未传递

**调试**: 查看浏览器控制台的日志，检查 `containerNumber` 字段

**示例**:

```json
{
  "containerNumber": "ABCD1234567"  // ✅ 正确
  "containerNumber": ""             // ❌ 错误
  "containerNumber": null           // ❌ 错误
}
```

---

### 问题 5: 网络错误

**错误信息**:

```
Failed to fetch
```

**原因**:

- 服务器未启动
- 网络连接问题
- API 路由错误

**解决方案**:

1. 检查开发服务器是否正在运行
2. 检查浏览器网络标签（F12 -> Network）
3. 确认 API 端点正确: `/api/factory-shipments/{id}/status`
