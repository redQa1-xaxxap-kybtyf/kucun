# 库存管理系统 UI 优化需求文档（PC + 移动端）

> 版本：v1.0  日期：2026-04-17  适用版本：kucun 1.0.42
> 受众：产品、设计、前端研发
> 目标：对标国内主流 ERP / SaaS（钉钉宜搭、金蝶云、用友 YonSuite、飞书、管家婆）体验，提升瓷砖行业从业者（仓管、销售、老板）日常高频操作的易用性与信息获取效率。

---

## 一、优化目标与度量

| 目标                 | 现状问题                                          | 量化指标                                 |
| -------------------- | ------------------------------------------------- | ---------------------------------------- |
| 信息密度与可扫描性   | 表格字号偏小、色块散乱，列表单屏记录数偏少       | 1280×800 主流列表单屏 ≥ 15 行可读        |
| 符合国内视觉习惯     | 蓝色过冷、无中式点缀，数字与中文混排缺节奏       | 统一主色 + 财务橙金辅色；中英文字号分级 |
| 移动端一只手操作     | 关键操作在顶部，拇指热区缺失；表格横向溢出       | 核心操作 90% 可在屏幕下半区完成          |
| 触达效率             | 新建/搜索/扫码等高频入口路径 >2 步               | 高频操作 ≤ 1 步触达                      |
| 可访问性（老年仓管）| 正文 12–14 px，触控目标 <40 px                    | 默认正文 ≥ 14 px；触控目标 ≥ 44 px       |

---

## 二、设计原则（中国用户视角）

1. **信息即效率**：列表/表格是国内 B 端核心交付物，优先保障密度，再谈留白。
2. **中式配色克制点缀**：主色延续蓝（`--primary-500`），辅以"财务金橙"表达金额、促销、预警；关键确认按钮可用"中国红"`#E34D59` 表达重要决策，而非装饰。
3. **数字与中文节奏**：金额、批次号使用等宽数字（`font-variant-numeric: tabular-nums`），中文 PingFang / 思源黑体，小字 12 px 仅用于辅助元信息。
4. **少动效多响应**：微动画 150–200 ms，去除不必要 breathe/scale 动画；loading 用骨架屏 + 顶部进度条。
5. **移动端以卡片为骨、抽屉为门**：移动端复杂筛选收进 `Sheet`，关键操作用底部悬浮按钮（FAB）或底部操作栏（类微信小程序表单）。
6. **一致性优先**：页面标题、搜索筛选、分页、空状态、错误态全站 5 件套统一。

## 三、全局视觉系统升级

### 3.1 色彩 Token（基于现有 `app/globals.css`）

| Token                   | 现值                   | 建议值                  | 理由                                           |
| ----------------------- | ---------------------- | ----------------------- | ---------------------------------------------- |
| `--primary-500`         | `215 100% 54.3%`       | `217 91% 52%`           | 与钉钉/飞书蓝靠近，降低荧光感                  |
| 新增 `--accent-gold`    | —                      | `36 96% 52%`            | 金额、VIP、利润等正向财务高亮                  |
| 新增 `--accent-red-cn`  | —                      | `354 76% 55%`           | 重要提交、审批通过、库存告急                   |
| `--color-bg-primary`    | `gray-50`              | `210 20% 98%`           | 增加一丝冷调，避免纯灰发闷                     |
| `--radius-medium`       | `0.375rem`             | `0.5rem`                | 国内用户偏好略明显圆角，但避免 ≥10px 的"果冻" |

**深色模式**：当前仅跟随系统 (`prefers-color-scheme`)，需补手动切换（设置页 + Header 下拉），并持久化到用户偏好。

### 3.2 字号与字重

```
标题 H1 20/28  semibold   页面主标题
标题 H2 16/24  semibold   卡片 / 模块标题
正文     14/22  regular    表格内容、表单
辅助     12/18  regular    时间、ID、标签
数字     tabular-nums,字重+1 金额、数量、批次号
```
中文字体栈：`PingFang SC, "Microsoft YaHei", "Source Han Sans SC", system-ui`。

### 3.3 间距、阴影、圆角

- 栅格基础 4 px；卡片内边距桌面 16 px / 移动 12 px。
- 阴影仅三档：`light`（卡片静态）、`medium`（悬浮）、`heavy`（Modal）；取消 inline `boxShadow`。
- 圆角：卡片 8 px，按钮 6 px，Tag/Badge 4 px，Modal 12 px。

### 3.4 图标

- 统一使用 lucide-react，尺寸 16/20/24；严禁混用 emoji 与 lucide。
- 为"瓷砖行业"高频操作补充语义：入库（箱形+下箭头）、出库（箱形+上箭头）、批次（条码）、色号（色卡）。

## 四、PC 端（≥1024px）优化需求

### 4.1 布局框架（对 `DashboardLayoutClient.tsx`）

| 模块          | 现状                              | 优化需求                                                                 |
| ------------- | --------------------------------- | ------------------------------------------------------------------------ |
| 顶栏 Header   | 高度较大，搜索/新建入口分散      | 高度 `48px`；集成全局搜索（`Cmd/Ctrl+K` Command Palette），右侧按组归类：通知 \| 账套切换 \| 帮助 \| 头像 |
| 侧边栏        | 展开 288 px / 收起 80 px          | 展开 `240px`、收起 `56px`（对标金蝶）；收起时 tooltip 展示全名；支持固定在右键菜单中"搜索菜单" |
| 面包屑        | 顶部 sticky，字号 xs uppercase    | 取消 `uppercase`（对中文无意义），字号 12/14，保留上一级可点击；添加"返回"箭头按钮 |
| 多标签页(新增)| 无                                | 参照金蝶云/用友，支持页面 Tab 多开，刷新/关闭/关闭其他；仅 PC 端启用     |
| 主内容 padding| 32 px                             | 24 px，给列表更多空间                                                    |

### 4.2 列表页（通用）

**结构标准**：`PageHeader → 统计条（可选） → UnifiedSearchBar → 筛选标签条 → 数据表格 → 分页`。

- **PageHeader**：去掉渐变背景，改为白底 + 左侧色条（主色/橙/绿区分模块），减少视觉噪音。
- **统计条**：在列表上方增加 4 个关键指标卡（如销售订单：今日新增 / 待审批 / 待发货 / 本月金额），支持点击作为快速筛选。
- **搜索筛选**：
  - 搜索框靠左，支持按条码、客户简码、订单号；
  - 筛选器以"标签 Chip"形式二次呈现已选条件，一键清除；
  - 高级筛选收进右侧抽屉，记忆上次使用的组合。
- **表格**：
  - 表头左对齐中文、右对齐数字，支持列设置（显示/隐藏/宽度）持久化到 localStorage；
  - 金额列使用 `tabular-nums` 并千分位；负数红色、正数金橙；
  - 行 hover 淡色高亮，选中行保持描边；
  - 行内操作合并进"更多"下拉，默认只露出 1–2 个高频按钮，避免一行 5+ 按钮；
  - 批量操作吸顶：勾选后出现浮层，展示"已选 N 条 + 批量按钮"。
- **分页**：居右；提供"每页 20/50/100"与"跳至第 X 页"；大表数据显示总条数。
- **空/错/加载**：统一使用 `empty-state` + `skeleton` + `error-boundary-fallback`，空状态文案中文化+建议操作（"暂无销售订单，立即新建"）。

### 4.3 表单页（创建/编辑）

- 两栏布局：左 70% 表单，右 30% 实时摘要/明细汇总（金额小计、库存可用量），对标管家婆开单界面。
- 字段分组用**分区卡片**，避免通篇长表单；必填项红色星号在标签左侧。
- "保存草稿 / 提交审批 / 保存并新建" 按钮固定在页面底部操作条（sticky footer），始终可见。
- 表单错误以红色底色行 + 顶部错误汇总链接定位。
- 新增**快捷键**：`Ctrl+S` 保存，`Alt+N` 新建行，`Esc` 取消。

### 4.4 详情页

- 顶部：面包屑 + 单号 + 状态徽章（色块文案并行，如"待审批"）+ 关键时间线。
- 左主 右辅：左侧为业务明细（Tabs：商品 / 收款 / 物流 / 日志），右侧为元信息（客户、业务员、备注、附件）。
- 日志 / 操作流水采用时间线组件。

### 4.5 仪表盘

- 顶部 4 张 KPI 卡 + 2 张趋势图（销售 7/30 日、库存周转）+ 2 张排行榜（畅销商品、欠款客户）。
- KPI 卡显示同比/环比箭头（绿/红），符合国内财务报表习惯。
- 所有图表数字支持"点击下钻到明细列表"。

## 五、移动端（≤768px）优化需求

### 5.1 整体导航

| 模块       | 现状                              | 优化需求                                                     |
| ---------- | --------------------------------- | ------------------------------------------------------------ |
| 顶栏       | 与 PC 同高                        | `44px`；左：菜单；中：页面标题（不可省略）；右：搜索 + 扫码 |
| 侧抽屉     | MobileNav 已存在                  | 增加用户信息头部 + 账套切换 + 最近使用（提升老用户效率）     |
| 底部 TabBar（新增）| 无                   | 4 个一级入口：**工作台 / 库存 / 订单 / 我的**；拇指可达       |
| 返回       | 靠面包屑                          | 详情页 / 表单页顶部固定"←"返回按钮，与原生一致               |

### 5.2 列表页移动端卡片

- 使用已存在的 `mobile-data-table`，但卡片内信息结构重排：
  - 第 1 行：主标题（订单号/商品名）+ 右侧状态 Badge；
  - 第 2 行：次要信息（客户 / 规格色号）；
  - 第 3 行：金额（大号金橙色，tabular-nums）+ 日期；
  - 右下角：展开菜单或主操作按钮。
- 整卡可点击进详情；长按调出快捷菜单（复制单号、分享、打印）。
- 顶部 sticky：搜索框 + 筛选按钮（带红点提示已选条件数）。
- 无限滚动替代分页；底部显示"—— 没有更多了 ——"。

### 5.3 搜索与筛选

- 搜索按钮点击后全屏搜索页：顶部输入 + 历史搜索 + 热门筛选（近 7 天、待审批等）。
- 筛选按钮打开 `Sheet` 从底部升起：分组字段，底部"重置 / 确定"双按钮（左灰右蓝，符合微信、淘宝惯例）。
- 所有日期筛选提供"今日/本周/本月/自定义"快捷组。

### 5.4 表单移动端

- 一屏一段，使用分步表单（Steps）代替长滚动，尤其是销售订单、入库单。
- 输入控件：
  - 数量、金额字段默认唤起**数字键盘**；
  - 商品选择器打开全屏弹层，支持**扫码 / 拍照识别色号**入口（预留 API）；
  - 客户选择器支持拼音首字母索引；
  - 日期选择器使用底部滚轮（与支付宝/微信一致）。
- 操作按钮固定在底部安全区，主按钮铺满宽度 + 阴影。

### 5.5 详情页

- 顶部状态横幅（彩色条）展示当前状态 + 预计下一步；
- 关键信息折叠卡片（默认展开"商品明细 / 金额"，折叠"日志"）；
- 底部固定操作栏：根据状态显示"审批 / 发货 / 收款 / 打印"；打印走微信分享图片路径。

### 5.6 触控与性能

- 所有可点击目标 ≥ `44×44 px`；行内图标点击区域撑满。
- 列表使用虚拟滚动（已存在 `virtualized-table`，移动端需适配）。
- 图片懒加载 + 缩略图走七牛云样式参数 `?imageMogr2/thumbnail/300x`。
- 离线：关键只读页面支持 SW 缓存，弱网提示"当前使用缓存数据"。

## 八、验收标准

1. **视觉**：全站页面遵循新 Token，无 inline 颜色；颜色对比度 WCAG AA。
2. **性能**：PC 首屏 LCP < 2.0s，移动端 < 2.5s；列表滚动 60fps。
3. **一致性**：所有列表页通过同一套 Header+Search+Table+Empty 模板渲染。
4. **可用性测试**：关键任务（新建销售订单、入库、收款）在不培训情况下成功率 ≥ 90%，平均耗时下降 ≥ 20%。
5. **回归**：原有 Jest 与 Playwright 用例全绿；新增核心组件单测。

## 九、风险与权衡

- **色彩变更风险**：主色轻微偏移会波及全站截图资料，需同步更新帮助中心；
- **多标签页成本**：与 Next.js App Router 路由模型冲突，需评估使用 iframe 容器或客户端路由缓存；
- **分步表单**：对现有销售订单表单重构工作量较大，建议先在"入库单"灰度；
- **老用户习惯**：底部 TabBar 与多标签页建议提供"切回经典布局"开关，降低迁移阵痛。
