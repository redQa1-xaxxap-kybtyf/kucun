## 1. 全局 UI 基础

### 1.1 设计令牌（Design Tokens）

**现状**（`app/globals.css:100-252`）：

- 完整 HSL 变量体系：primary / purple / cyan / success / warning / error / info + gray 10 阶
- 语义化令牌齐全：bg-primary/secondary/tertiary/card、text-primary/secondary/tertiary/disabled、border-primary/secondary/strong
- 圆角三档：small 0.25rem / medium 0.375rem / large 0.5rem（偏保守，符合 ERP 风格）
- 阴影三档：light / medium / heavy
- 暗黑模式：`@media (prefers-color-scheme: dark)` 已覆盖（`app/globals.css:261-289`）

**问题**：

| 级别 | 问题 | 证据 |
|---|---|---|
| 🟡 | 主色 `--primary-500: hsl(215 100% 54.3%)` 饱和度 100%，比 AntD Blue-6 (#1677ff ≈ 215 90% 54%) 更艳，长时间看易疲劳 | `globals.css:103` |
| 🟡 | error-500 / warning-500 饱和度 95~100%，中国企业用户偏稳重，建议下调至 70~85% | `globals.css:121-127` |
| 🟡 | 令牌定义存在但组件层大量硬编码：dashboard 用 `rounded-3xl` / `rounded-[32px]` / `bg-white/40` 绕过令牌 | `components/dashboard/erp-dashboard.tsx:24,38,55` |
| 🟢 | 无"品牌色"语义分层（primary ≠ brand），跨品牌定制成本高 | — |

**与参考系差距**：AntD 令牌有完整的 8 档色阶（1~10），项目仅 3~5 档（50/100/400/500/600），不足以覆盖 hover / active / disabled / selected / focus 全状态；ERP 系统常需要 `table-row-selected / table-row-hover / link-visited` 等细分 token。

### 1.2 字体与排版

**现状**：

- `app/globals.css:296-300` 仅设置 `font-feature-settings: 'liga','kern'`，**未声明 font-family**
- 全局工具类 `text-table-header` 使用 `uppercase + letter-spacing 0.08em`（`globals.css:463-469`）
- 面包屑使用 `text-xs font-black tracking-widest uppercase text-slate-500`（`DashboardLayoutClient.tsx:307`）

**问题**：

| 级别 | 问题 | 证据 |
|---|---|---|
| 🔴 | **未显式声明中文字体栈**：生产环境将退化到浏览器/操作系统默认，Windows 下是"微软雅黑"，macOS 下是"苹方"，Linux 下可能是英文无衬线（中文方块）。必须显式声明 `-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Source Han Sans CN", sans-serif` | `globals.css:296` |
| 🔴 | `uppercase` + `tracking-widest` 对**中文完全无效**（中文没有大小写），只在中英混排时让英文变丑；`letter-spacing 0.08em` 对中文反而破坏阅读节奏（每个汉字后都加间隙） | `globals.css:467`、`DashboardLayoutClient.tsx:307` |
| 🟡 | `font-black` (900) 用在面包屑这种次要信息上，字重使用颠倒；AntD/ERP 普遍用 regular 400~medium 500 | `DashboardLayoutClient.tsx:307` |
| 🟡 | 表格正文 `text-xs` (12px) 没问题，但未定义统一字号梯度（11/12/13/14/16/20），组件层自由发挥 | — |
| 🟢 | 数字类字段未用等宽数字字体（`font-variant-numeric: tabular-nums`），金额/数量在列表中对不齐 | — |

**与参考系差距**：AntD 有完整的 `--font-family / --font-family-code` 和 7 档字号（12/14/16/20/24/30/38/46）；行业 ERP（管家婆/金蝶）偏好 13~14px 正文 + 12px 辅助，且金额字段强制 `tabular-nums` 右对齐。

### 1.3 布局骨架

**现状**（`components/common/DashboardLayoutClient.tsx`）：

- 三区布局：Header（固定顶部）+ Sidebar（固定左侧 288px / 折叠 80px）+ Main（可滚动）
- 断点：`isMobile` ≤ 768px → 抽屉式 MobileNav；`isTablet` 769~1024px → 自动折叠侧边栏；>1024px → 完整侧边栏
- 面包屑置于主内容区顶部 sticky（`DashboardLayoutClient.tsx:296-310`）
- 使用 `bg-white/40 backdrop-blur-md` 毛玻璃效果

**问题**：

| 级别 | 问题 | 证据 |
|---|---|---|
| 🟡 | 断点切换依赖 JS 的 `useMediaQuery` hook，不是纯 CSS 响应式 → SSR 首屏与客户端不一致，会有闪烁/布局跳动 | `DashboardLayoutClient.tsx:103-104` |
| 🟡 | 毛玻璃 `backdrop-blur-md bg-white/40` 在 ERP 场景反而显"轻飘"，金蝶/用友等标配白底+1px 下边框 | `DashboardLayoutClient.tsx:299` |
| 🟡 | 面包屑 `border-slate-50`（几乎看不见）+ 毛玻璃背景 → 层次模糊；应使用语义化 `border-border` | `DashboardLayoutClient.tsx:299` |
| 🟢 | 主内容区左边距硬编码 `ml-72` / `ml-20`（`DashboardLayoutClient.tsx:289`），与侧边栏实际宽度耦合，难统一调整 | — |
| 🟢 | 缺少"固定页面标题区 + 筛选区 + 表格区"的标准 ERP 三段式骨架组件 | — |

**与参考系差距**：AntD Pro 的 `PageContainer` 提供标题/面包屑/Tab/操作区/内容区五段式；本项目每个页面各自实现 header，样式不统一。

## 2. 仪表板（Dashboard）

### 2.1 页面结构

**现状**（`components/dashboard/erp-dashboard.tsx`）：KPI 卡片（4 列）+ 趋势图（480px 高）+ 待办条 + 最近订单 + 产品排行 + 快捷操作。

**问题**：

| 级别 | 问题 | 证据 |
|---|---|---|
| 🔴 | `rounded-3xl` (1.5rem) / `rounded-[32px]` 大圆角 + `bg-white/40` 半透明卡片 + `h-[160px]` 超高 KPI 卡片 = 典型欧美 SaaS 风格，与国内 ERP（金蝶云星空/用友 U8）"白底+小圆角 4px+密集信息"相差极大；中国企业用户第一眼会觉得"像玩具"而非"干活的工具" | `erp-dashboard.tsx:24,38,55` |
| 🔴 | KPI 卡高 160px，主流 ERP ≤ 96px；一屏可见信息量过低 | 同上 |
| 🟡 | 趋势图固定 480px 高，占屏幅过大；管家婆/旺店通的仪表盘趋势图通常 240~320px | 同上 |
| 🟡 | 没看到"今日关键数字横向条"（今日营收/今日订单数/今日发货数/今日收款）这种国内 ERP 首屏必备信息 | — |
| 🟡 | 最近订单/待处理订单/厂家发货被拆成三个模块，信息冗余；应合并为带 Tab 的单一"订单动态" | — |
| 🟢 | 注释自称"ERP风格的紧凑布局"但实际视觉是欧美 SaaS 风（`erp-dashboard.tsx:74-81`），言行不一 | — |

**对标**：金蝶云星空首页 = 顶部 6 格 KPI（每个 ≤80px 高）+ 左侧待办 + 右上图表 + 右下动态，一屏能看 ≥ 20 条信息；本项目一屏约 5~8 条。

## 7. 移动端响应式综合审查

### 7.1 已具备能力

- `useMediaQuery` + `MobileNav` 抽屉导航（`DashboardLayoutClient.tsx:103,273-279`）
- `MobileDataTable` 桌面表格 → 移动卡片自动降级（`components/ui/mobile-data-table.tsx`）
- 触屏左右滑手势打开/关闭侧边栏（`DashboardLayoutClient.tsx:210-233`）
- `Sheet` 组件可用（`components/ui/sheet.tsx`），适合抽屉式表单
- 断点：`md: 768px / lg: 1024px`，基本符合国内约定

### 7.2 主要问题

| 级别 | 问题 |
|---|---|
| 🔴 | 断点依赖 JS hook 而非纯 CSS，SSR 首屏会"先桌面后移动"闪烁；主流做法是 Tailwind `md:/lg:` 前缀 + 关键交互才用 hook |
| 🔴 | 大量表单类页面（订单新建/库存盘点）在移动端直接复用桌面版 Dialog 而非 Sheet/全屏页，窄屏下按钮易被遮 |
| 🟡 | `MobileDataTable` 卡片模式：单卡片展示信息密度不足（瓷砖经销商经常一卡要显示品名/规格/SKU/单价/库存/操作 6+ 字段），需要支持"双列卡片"布局 |
| 🟡 | 数字键盘未强制 `inputMode="numeric" / "decimal"`，财务/数量输入在移动端会弹全键盘 |
| 🟡 | 固定底部操作条（"保存/提交/返回"）在移动端惯例是 `fixed bottom-0`，需验证各表单页是否实现；未实现时用户要滚到底再点，体验差 |
| 🟢 | 移动端搜索没看到"语音输入"入口（国内用户习惯） |
| 🟢 | 顶部 Header 在移动端的"返回按钮 + 标题 + 操作菜单" iOS/Android 约定栏是否落实，需逐页核验 |

## 8. 中国用户审美与体验差距（总结）

| 维度 | 当前风格 | 国内 ERP / AntD 惯例 | 差距 |
|---|---|---|---|
| 圆角 | 混用 4px / 6px / 8px / 24px / 32px | 统一 2~6px | 🔴 需收敛 |
| 卡片背景 | 半透明 `bg-white/40` + 大阴影 | 实色白 + 1px 浅灰边 + 极淡阴影 | 🔴 风格偏移 |
| 字体 | 未显式声明 | 苹方/雅黑/思源黑体栈 | 🔴 必须补 |
| 字重 | 面包屑 `font-black` 等滥用 | 主体 regular 400，强调 medium 500 / semibold 600 | 🟡 需统一 |
| 大小写 | `uppercase tracking-widest` 对中文无效 | 中文不做大小写变换 | 🟡 需移除 |
| 色彩饱和度 | 95~100% | 70~85%（稳重） | 🟡 需下调 |
| 信息密度 | 稀疏（KPI 160px） | 密集（KPI ≤ 96px） | 🔴 需增密 |
| 表格密度 | 默认 comfortable | 默认 compact + 可切 | 🟡 需调默认 |
| 数字对齐 | 无 tabular-nums | 金额/数量 tabular-nums 右对齐 | 🔴 必须补 |
| 按钮风格 | shadcn 圆角中性 | 主操作实色填充 + 次要描边 + 危险操作红色文字链 | 🟡 需审查各页 |
| 空状态 | EmptyState 组件齐全 | 图+文+行动按钮 | 🟢 可用 |
