## 🚨 紧急问题

### 问题1: Prisma Client生成失败 - EPERM错误

**错误信息**:

```
Error: EPERM: operation not permitted, rename
'query_engine-windows.dll.node'
```

**原因**: 开发服务器正在运行,占用了Prisma Query Engine文件

**解决方案**:

```bash
# 1. 停止开发服务器 (在终端按 Ctrl+C)

# 2. 或者强制终止进程
# Windows:
taskkill /F /IM node.exe

# 3. 重新生成Prisma Client
npx prisma generate

# 4. 重新启动开发服务器
npm run dev
```

**预防措施**:

- 修改Schema后,先停止服务器再生成Client
- 使用 `npm run db:generate` 脚本(自动处理)

### 问题2: API返回PrismaClientValidationError

**错误信息**:

```
Invalid `prisma.model.findMany()` invocation
Unknown field `relationName` for select statement
```

**原因**: Prisma Schema中缺少关系定义

**解决方案**:

```prisma
// 1. 检查Schema中是否有关系定义
model OutboundRecord {
  id        String   @id @default(cuid())
  variantId String?

  // ❌ 缺少关系定义
}

// 2. 添加关系定义
model OutboundRecord {
  id        String          @id @default(cuid())
  variantId String?
  variant   ProductVariant? @relation(fields: [variantId], references: [id], onDelete: SetNull, onUpdate: Cascade)

  @@index([variantId])
}

// 3. 添加反向关系
model ProductVariant {
  id              String           @id @default(cuid())
  outboundRecords OutboundRecord[]  // 反向关系
}

// 4. 重新生成Prisma Client
npx prisma generate
```

**验证修复**:

```bash
npm run validate:schema
```

### 问题3: TypeScript错误 - Property does not exist

**错误信息**:

```typescript
Property 'inventory' does not exist on type 'ProductVariant'
```

**原因**: Prisma Schema中缺少关系,或者使用了错误的关系名称

**解决方案**:

```typescript
// ❌ 错误代码
const variant = await prisma.productVariant.findUnique({
  where: { id },
  include: {
    inventory: true,  // ❌ ProductVariant没有inventory关系
  }
});

// ✅ 方案1: 添加关系到Schema
// prisma/schema.prisma
model ProductVariant {
  inventory Inventory[]  // 添加关系
}

// ✅ 方案2: 使用正确的查询方式
const variant = await prisma.productVariant.findUnique({
  where: { id },
});

const inventory = await prisma.inventory.findMany({
  where: { variantId: id }
});
```

## ⚠️ 常见错误

### 错误1: Zod验证 - required_error已废弃

**错误信息**:

```typescript
Argument of type '{ required_error: string; }' is not assignable
```

**解决方案**:

```typescript
// ❌ 错误 (Zod 3语法)
feeType: z.enum(['freight', 'processing'], {
  required_error: '请选择费用类型',
});

// ✅ 修复 (Zod 4语法)
feeType: z.enum(['freight', 'processing'], {
  message: '请选择费用类型',
});

// 或者
feeType: z.enum(['freight', 'processing']).refine(val => val !== undefined, {
  message: '请选择费用类型',
});
```

**批量查找**:

```bash
grep -r "required_error" --include="*.ts" lib/validations/
```

### 错误2: 隐式any类型

**错误信息**:

```typescript
Parameter 'data' implicitly has an 'any' type
```

**解决方案**:

```typescript
// ❌ 错误
function handleSubmit(data) {
  // 隐式any
  console.log(data);
}

// ✅ 修复 - 明确类型
interface FormData {
  name: string;
  value: number;
}

function handleSubmit(data: FormData) {
  console.log(data);
}

// ✅ 修复 - 使用泛型
function handleSubmit<T>(data: T) {
  console.log(data);
}

// ✅ 修复 - 使用unknown
function handleSubmit(data: unknown) {
  if (typeof data === 'object' && data !== null) {
    console.log(data);
  }
}
```

### 错误3: 可选字段类型不匹配

**错误信息**:

```typescript
Type 'string | undefined' is not assignable to type 'string'
```

**解决方案**:

```typescript
// ❌ 错误
const supplierId: string = data.supplierId; // data.supplierId可能是undefined

// ✅ 修复1: 使用可选类型
const supplierId: string | undefined = data.supplierId;

// ✅ 修复2: 提供默认值
const supplierId: string = data.supplierId ?? '';

// ✅ 修复3: 类型守卫
if (data.supplierId) {
  const supplierId: string = data.supplierId;
}

// ✅ 修复4: 非空断言 (确定不为空时)
const supplierId: string = data.supplierId!;
```

## 🔧 性能问题

### 问题1: N+1查询

**症状**: API响应慢,数据库查询次数多

**检测方法**:

```typescript
// 查看慢查询日志
// lib/db.ts 中的慢查询监控会自动记录
```

**解决方案**:

```typescript
// ❌ N+1查询
const orders = await prisma.salesOrder.findMany();
for (const order of orders) {
  const customer = await prisma.customer.findUnique({
    where: { id: order.customerId },
  });
  order.customer = customer;
}

// ✅ 使用include
const orders = await prisma.salesOrder.findMany({
  include: {
    customer: true,
  },
});

// ✅ 批量查询
const orders = await prisma.salesOrder.findMany();
const customerIds = orders.map(o => o.customerId);
const customers = await prisma.customer.findMany({
  where: { id: { in: customerIds } },
});
const customerMap = new Map(customers.map(c => [c.id, c]));
orders.forEach(order => {
  order.customer = customerMap.get(order.customerId);
});
```

### 问题2: 过度查询数据

**症状**: API返回大量不需要的数据

**解决方案**:

```typescript
// ❌ 查询所有字段
const products = await prisma.product.findMany();

// ✅ 只查询需要的字段
const products = await prisma.product.findMany({
  select: {
    id: true,
    name: true,
    code: true,
    // 不查询description、specifications等大字段
  },
});

// ✅ 使用_count替代include
const customers = await prisma.customer.findMany({
  select: {
    id: true,
    name: true,
    _count: {
      select: {
        salesOrders: true, // 只获取数量,不加载数据
      },
    },
  },
});
```

### 问题3: 缺少数据库索引

**症状**: 查询慢,数据库CPU高

**检测方法**:

```sql
-- MySQL: 查看慢查询
SHOW FULL PROCESSLIST;

-- 查看表的索引
SHOW INDEX FROM sales_orders;
```

**解决方案**:

```sql
-- 添加常用查询的索引
CREATE INDEX idx_sales_orders_customer_status
  ON sales_orders(customer_id, status);

CREATE INDEX idx_sales_orders_order_date
  ON sales_orders(order_date DESC);

CREATE INDEX idx_inventory_product_batch
  ON inventory(product_id, batch_number);
```

**Prisma Schema中添加索引**:

```prisma
model SalesOrder {
  id         String   @id @default(cuid())
  customerId String
  status     String
  orderDate  DateTime

  @@index([customerId, status])
  @@index([orderDate(sort: Desc)])
}
```
