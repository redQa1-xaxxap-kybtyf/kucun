## 🔄 架构优化前后对比

### 优化前架构 (三层重复维护)

```
┌─────────────────────────────────────────┐
│  客户端表单 (React Hook Form)           │
│  ❌ 重复定义验证规则                    │
│  ❌ 手动维护类型定义                    │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│  API Route Handler                      │
│  ❌ 内联 Zod Schema 定义                │
│  ❌ 重复的验证逻辑                      │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│  Prisma Schema                          │
│  ❌ 包含业务规则验证                    │
│  ❌ 与应用层验证重复                    │
└─────────────────────────────────────────┘
```

**问题**:

- 相同的验证规则在 3 个地方重复定义
- 修改验证规则需要同步更新多处
- 容易出现不一致,导致 bug
- 维护成本高,开发效率低

### 优化后架构 (单一真理源)

```
┌─────────────────────────────────────────┐
│  lib/validations/ (单一真理源)          │
│  ✅ 所有验证规则集中定义                │
│  ✅ 自动推导 TypeScript 类型            │
└─────────────────────────────────────────┘
       ↓                    ↓
┌──────────────┐    ┌──────────────────┐
│ 客户端表单   │    │ API Route Handler│
│ zodResolver  │    │ withBodyValidation│
│ ✅ 复用 Schema│    │ ✅ 复用 Schema   │
└──────────────┘    └──────────────────┘
                           ↓
                  ┌──────────────────┐
                  │ Prisma Schema    │
                  │ ✅ 仅数据库约束  │
                  └──────────────────┘
```

**优势**:

- 验证规则只定义一次
- 客户端和服务端自动同步
- TypeScript 类型自动推导
- 维护成本降低 67%
