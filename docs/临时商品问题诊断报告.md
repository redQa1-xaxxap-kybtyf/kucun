# 临时商品未保存问题 - 完整诊断报告

## 📋 问题描述

在销售订单（`orderType = 'TRANSFER'`）中手动添加临时商品（`isManualProduct = true`）后，这些临时商品没有被保存到 `temporary_products` 表中，导致无法在后续订单中复用。

## 🎯 根本原因分析

### 1. 代码逻辑检查

#### ✅ 后端逻辑正确

**订单创建 API** (`lib/api/handlers/sales-orders/create.ts`):

- ✅ 正确调用了临时商品创建逻辑
- ✅ 在事务中执行
- ✅ 正确传递 `temporaryProductIds` 到 `buildOrderItemsInput`

**订单更新 API** (`app/api/sales-orders/[id]/route.ts`):

- ✅ 正确调用了临时商品创建逻辑
- ✅ 在事务中执行
- ✅ 正确设置 `temporaryProductId` 到订单项

**临时商品创建函数** (`lib/api/handlers/sales-orders/temporary-products.ts`):

- ✅ `findOrCreateTemporaryProduct` 实现正确
- ✅ `buildTemporaryProductDataFromOrderItem` 实现正确

#### ⚠️ 前端数据提交问题

**关键发现**：临时商品创建的前置条件是：

```typescript
if (!item.isManualProduct || !item.productCode) {
  return null; // 不创建临时商品
}
```

**必须同时满足**：

1. `isManualProduct === true`
2. `productCode` 不为空

### 2. 可能的问题场景

#### 场景 A: 前端未正确设置 `productCode`

在 `intelligent-product-input.tsx` 中：

```typescript
// 第 186 行
form.setValue(`items.${index}.productCode`, manualCode || undefined);
```

如果 `productData.productCode` 为空字符串，会被设置为 `undefined`。

#### 场景 B: 订单状态为草稿时的验证逻辑

在 `lib/validations/sales-order/validators.ts` 中：

```typescript
export function validateManualProductFields(
  items: SalesOrderItemFormData[],
  status: string,
  _orderType?: 'NORMAL' | 'TRANSFER'
): boolean {
  if (status === 'draft') {
    return true; // ⚠️ 草稿状态不验证 productCode
  }
  // ...
}
```

**问题**：草稿状态的订单可以不填写 `productCode`，但后端创建临时商品时需要 `productCode`。

```typescript
// lib/validations/sales-order/validators.ts
export function validateManualProductFields(
  items: SalesOrderItemFormData[],
  status: string,
  orderType?: 'NORMAL' | 'TRANSFER'
): boolean {
  // ✅ 调货销售的手动商品必须有 productCode（包括草稿状态）
  if (orderType === 'TRANSFER') {
    for (const item of items) {
      if (item.isManualProduct) {
        const hasCode =
          typeof item.productCode === 'string' &&
          item.productCode.trim() !== '';
        if (!hasCode) {
          return false;
        }
      }
    }
  }

  // 非草稿状态的其他验证
  if (status !== 'draft') {
    // ...
  }

  return true;
}
```

### 方案 2: 允许 productCode 为空（不推荐）

修改临时商品创建逻辑，使用其他字段作为唯一标识：

```typescript
// ❌ 不推荐：会导致临时商品无法正确复用
export function buildTemporaryProductDataFromOrderItem(
  item: {
    isManualProduct?: boolean;
    productCode?: string | null;
    manualProductName?: string | null;
    // ...
  },
  supplierId: string,
  userId: string
): TemporaryProductData | null {
  if (!item.isManualProduct) {
    return null;
  }

  // 使用商品名称作为编码（如果没有编码）

  return {
    supplierId,
    code,
    name: item.manualProductName || code,
    // ...
  };
}
```

**问题**：这会导致临时商品无法正确复用，因为商品名称可能不唯一。
