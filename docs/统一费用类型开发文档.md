## 📊 执行摘要

### 核心问题

当前系统存在**4处不同的费用类型定义**,导致:

1. **定义不一致**: `shipping` vs `freight` 都表示运费
2. **分类不完整**: 销售订单费用只有3种类型,无法覆盖所有业务场景
3. **维护困难**: 修改费用类型需要同时更新多个文件
4. **统计混乱**: 财务报表无法准确统计各类费用

### 解决方案

**核心设计原则**:
- **单一数据源**: 建立统一的费用类型定义作为唯一真实来源
- **类型安全**: 使用TypeScript字符串字面量联合类型,而非枚举
- **分类清晰**: 区分直接费用(可分摊)和间接费用(期间费用)
- **易于扩展**: 支持新增费用类型而无需修改数据库Schema

## 🎯 技术选型与最佳实践

### TypeScript类型系统选择

基于2025年最新最佳实践研究,我们选择**字符串字面量联合类型 (String Literal Union Types)**作为费用类型的实现方式。

#### 为什么不使用枚举 (Enum)?

```typescript
// ❌ 不推荐: TypeScript 枚举存在的问题
enum ExpenseType {
  SHIPPING = 'shipping',
  STORAGE = 'storage',
}

// 问题1: 数值枚举类型不安全
enum Status {
  Draft = 0,
  Active = 1,
}
const status: Status = 999; // ✅ TypeScript不会报错,但实际上是无效值

// 问题2: 运行时代码膨胀
// 枚举会生成额外的JavaScript代码,增加打包体积

// 问题3: 难以与外部系统集成
// 需要额外的映射逻辑
```

#### 为什么使用字符串字面量联合类型?

```typescript
// ✅ 推荐: 字符串字面量联合类型
export type ExpenseType =
  | 'freight'      // 运费
  | 'storage'      // 仓储费
  | 'processing'   // 加工费
  | 'labor'        // 人工费
  | 'other';       // 其他费用

// 优势1: 完全的类型安全
const expense: ExpenseType = 'invalid'; // ❌ TypeScript 编译错误

// 优势2: 零运行时开销
// 编译后只是普通字符串,无额外代码

// 优势3: 易于扩展
type ExtendedExpenseType = ExpenseType | 'customs' | 'inspection';

// 优势4: 与数据库无缝集成
// 数据库存储VARCHAR,无需类型转换
```

**2025年社区共识**:
- 40% 的开发者倾向于使用枚举管理有限集合
- 25% 的开发者偏好字符串字面量联合类型
- **关键发现**: 在需要与外部系统(如数据库、API)集成时,**字符串字面量联合类型的类型安全性和灵活性更优**

### Prisma Schema设计原则

#### 为什么不使用数据库级枚举?

```prisma
// ❌ 不推荐: 数据库枚举
enum ExpenseType {
  FREIGHT
  STORAGE
  PROCESSING
}

model ExpenseRecord {
  expenseType ExpenseType
}
```

**问题**:
1. **修改困难**: 添加新类型需要数据库迁移
2. **数据库限制**: 仅支持 PostgreSQL、MySQL 和 MongoDB
3. **维护成本高**: 频繁变更的枚举会导致大量迁移文件

#### 为什么使用VARCHAR存储?

```prisma
// ✅ 推荐: 使用String类型 + TypeScript约束
model ExpenseRecord {
  expenseType String @map("expense_type") @db.VarChar(50)
  // 值域由TypeScript类型系统保证
}
```

**优势**:
1. **灵活扩展**: 添加新类型无需数据库迁移
2. **跨数据库兼容**: 所有数据库都支持VARCHAR
3. **降低耦合**: 业务逻辑与数据库Schema解耦
4. **开发效率**: 减少迁移文件数量,加快开发速度

## 🗄️ 统一费用类型设计

### 核心类型定义

```typescript
// lib/types/unified-expense.ts

/**
 * 统一的费用类型定义
 *
 * 设计原则:
 * 1. 使用中文注释明确每种费用的业务含义
 * 2. 使用英文小写加下划线的命名约定 (数据库友好)
 * 3. 分类清晰,易于财务统计和报表分析
 *
 * 适用范围:
 * - ExpenseRecord (费用记录)
 * - SalesOrderFeeItem (销售订单费用)
 * - FactoryShipmentFeeItem (厂家发货费用)
 * - PurchaseOrderExpense (采购订单费用)
 */
export type UnifiedExpenseType =
  // === 运输相关 (Transportation) ===
  | 'freight'           // 运费 (国内/国际运输)
  | 'loading_unloading' // 装卸费
  | 'packaging'         // 包装费

  // === 仓储相关 (Warehousing) ===
  | 'storage'           // 仓储费
  | 'rent'              // 租金

  // === 加工相关 (Processing) ===
  | 'processing'        // 加工费
  | 'labor'             // 人工费

  // === 行政相关 (Administrative) ===
  | 'management'        // 管理费用
  | 'utilities'         // 水电费
  | 'travel'            // 差旅费
  | 'living'            // 生活费

  // === 贸易相关 (Trade) ===
  | 'customs'           // 报关费/关税
  | 'inspection'        // 检验费
  | 'insurance'         // 保险费

  // === 其他 (Others) ===
  | 'depreciation'      // 折旧
  | 'other';            // 其他费用

/**
 * 费用类型的中文标签映射
 * 用于前端显示和报表生成
 */
export const UNIFIED_EXPENSE_TYPE_LABELS: Record<UnifiedExpenseType, string> = {
  freight: '运费',
  loading_unloading: '装卸费',
  packaging: '包装费',
  storage: '仓储费',
  rent: '租金',
  processing: '加工费',
  labor: '人工费',
  management: '管理费用',
  utilities: '水电费',
  travel: '差旅费',
  living: '生活费',
  customs: '报关费',
  inspection: '检验费',
  insurance: '保险费',
  depreciation: '折旧',
  other: '其他费用',
} as const;

/**
 * 费用分类
 *
 * 用于区分费用的会计处理方式:
 * - 直接费用: 可以直接分摊到产品成本
 * - 间接费用: 计入期间费用,不分摊到产品
 */
export const EXPENSE_CATEGORIES = {
  DIRECT: 'direct',     // 直接费用
  INDIRECT: 'indirect', // 间接费用
} as const;

export type ExpenseCategory = (typeof EXPENSE_CATEGORIES)[keyof typeof EXPENSE_CATEGORIES];

/**
 * 费用类型与分类的映射关系
 *
 * 会计处理规则:
 * - direct: 计入主营业务成本,影响毛利率
 * - indirect: 计入期间费用,不影响毛利率
 */
export const EXPENSE_TYPE_CATEGORY_MAP: Record<UnifiedExpenseType, ExpenseCategory> = {
  // 直接费用 (可分摊到产品)
  freight: 'direct',
  loading_unloading: 'direct',
  packaging: 'direct',
  storage: 'direct',
  processing: 'direct',
  labor: 'direct',
  customs: 'direct',
  inspection: 'direct',
  insurance: 'direct',

  // 间接费用 (期间费用)
  rent: 'indirect',
  management: 'indirect',
  utilities: 'indirect',
  travel: 'indirect',
  living: 'indirect',
  depreciation: 'indirect',
  other: 'indirect',
} as const;

/**
 * 获取费用类型的分类
 */
export function getExpenseCategory(expenseType: UnifiedExpenseType): ExpenseCategory {
  return EXPENSE_TYPE_CATEGORY_MAP[expenseType];
}

/**
 * 判断费用是否为直接费用(可分摊)
 */
export function isDirectExpense(expenseType: UnifiedExpenseType): boolean {
  return EXPENSE_TYPE_CATEGORY_MAP[expenseType] === 'direct';
}

/**
 * 获取所有直接费用类型
 */
export function getDirectExpenseTypes(): UnifiedExpenseType[] {
  return Object.entries(EXPENSE_TYPE_CATEGORY_MAP)
    .filter(([_, category]) => category === 'direct')
    .map(([type]) => type as UnifiedExpenseType);
}

/**
 * 获取所有间接费用类型
 */
export function getIndirectExpenseTypes(): UnifiedExpenseType[] {
  return Object.entries(EXPENSE_TYPE_CATEGORY_MAP)
    .filter(([_, category]) => category === 'indirect')
    .map(([type]) => type as UnifiedExpenseType);
}

/**
 * 费用类型选项 (用于表单下拉选择)
 */
export const UNIFIED_EXPENSE_TYPE_OPTIONS = Object.entries(UNIFIED_EXPENSE_TYPE_LABELS).map(
  ([value, label]) => ({
    value: value as UnifiedExpenseType,
    label,
    category: EXPENSE_TYPE_CATEGORY_MAP[value as UnifiedExpenseType],
  })
);

/**
 * 按分类分组的费用类型选项
 */
export const GROUPED_EXPENSE_TYPE_OPTIONS = [
  {
    label: '直接费用 (可分摊)',
    options: UNIFIED_EXPENSE_TYPE_OPTIONS.filter(opt => opt.category === 'direct'),
  },
  {
    label: '间接费用 (期间费用)',
    options: UNIFIED_EXPENSE_TYPE_OPTIONS.filter(opt => opt.category === 'indirect'),
  },
];
```

## 🔄 数据迁移方案

### Prisma Schema 无需修改

当前的Prisma Schema已经使用 `String` 类型存储费用类型,**无需数据库迁移**:

```prisma
// prisma/schema.prisma

// ✅ 现有Schema已经是最佳实践
model ExpenseRecord {
  // ...
  expenseType String @map("expense_type") @db.VarChar(50)
  // 值域: UnifiedExpenseType (由TypeScript类型系统保证)
}

model SalesOrderFeeItem {
  // ...
  feeType String @map("fee_type") @db.VarChar(50)
  // 值域: SalesOrderFeeType (UnifiedExpenseType的子集)
}
```

### 数据一致性检查 (可选)

如果担心现有数据中存在无效的费用类型值,可以执行以下SQL检查:

```sql
-- 检查 ExpenseRecord 表中的费用类型
SELECT DISTINCT expense_type
FROM expense_records
WHERE expense_type NOT IN (
  'freight', 'loading_unloading', 'packaging',
  'storage', 'rent',
  'processing', 'labor',
  'management', 'utilities', 'travel', 'living',
  'customs', 'inspection', 'insurance',
  'depreciation', 'other'
);

-- 检查 SalesOrderFeeItem 表中的费用类型
SELECT DISTINCT fee_type
FROM sales_order_fee_items
WHERE fee_type NOT IN (
  'freight', 'processing', 'packaging', 'loading_unloading', 'other'
);
```

如果查询返回任何结果,需要手动修正这些无效数据。

### 历史数据映射 (如果有命名不一致)

如果历史数据中使用了 `'shipping'` 而非 `'freight'`,需要执行数据更新:

```sql
-- 更新 ExpenseRecord 表
UPDATE expense_records
SET expense_type = 'freight'
WHERE expense_type = 'shipping';

-- 更新 SalesOrderFeeItem 表
UPDATE sales_order_fee_items
SET fee_type = 'freight'
WHERE fee_type = 'shipping';
```

## 🎨 前端表单组件

### 费用类型选择器

```typescript
// components/forms/expense-type-select.tsx

import React from 'react';
import {
  Select,
  SelectContent,
  SelectItem,
  SelectTrigger,
  SelectValue,
} from '@/components/ui/select';
import {
  GROUPED_EXPENSE_TYPE_OPTIONS,
  type UnifiedExpenseType,
} from '@/lib/types/unified-expense';

interface ExpenseTypeSelectProps {
  value?: UnifiedExpenseType;
  onChange: (value: UnifiedExpenseType) => void;
  placeholder?: string;
  disabled?: boolean;
}

export function ExpenseTypeSelect({
  value,
  onChange,
  placeholder = '请选择费用类型',
  disabled = false,
}: ExpenseTypeSelectProps) {
  return (
    <Select value={value} onValueChange={onChange} disabled={disabled}>
      <SelectTrigger>
        <SelectValue placeholder={placeholder} />
      </SelectTrigger>
      <SelectContent>
        {GROUPED_EXPENSE_TYPE_OPTIONS.map(group => (
          <React.Fragment key={group.label}>
            <div className="px-2 py-1.5 text-sm font-semibold text-muted-foreground">
              {group.label}
            </div>
            {group.options.map(option => (
              <SelectItem key={option.value} value={option.value}>
                {option.label}
              </SelectItem>
            ))}
          </React.Fragment>
        ))}
      </SelectContent>
    </Select>
  );
}
```
