## 🎯 核心设计亮点

### 1. 简单至上 (KISS)

**采用加权平均法**，避免复杂的FIFO/LIFO实现：

```typescript
新单位成本 = (原库存金额 + 入库金额) / (原库存数量 + 入库数量);
```

**复用现有表结构**，期初库存使用 InboundRecord 表：

```typescript
// 无需新增表，只需新增 reason 枚举值
reason: 'initial_stock';
```

**采用Excel批量导入**，而非复杂的成本建议算法：

```typescript
// ❌ 不开发：成本建议算法（系统初次上线无历史数据）
// ✅ 采用：Excel批量导入（行业标准做法）
```

### 2. 精益求精 (YAGNI)

**只实现当前明确需要的功能**：

- ✅ 期初库存录入（必需）
- ✅ Excel批量导入（必需）
- ✅ 批次和色号管理（瓷砖行业必需）
- ✅ 盘点差异处理（必需）
- ✅ 成本调整（必需）
- ❌ 成本建议算法（系统初次上线不适用）
- ❌ 多仓库成本核算（暂不需要）
- ❌ 批次成本追溯（暂不需要）

### 3. 数据准确性

**所有成本计算保留2位小数**：

```typescript
export function roundToTwoDecimals(value: number): number {
  return Math.round(value * 100) / 100;
}
```

**使用事务保证一致性**：

```typescript
await prisma.$transaction(async tx => {
  // 1. 创建入库记录
  // 2. 更新库存成本
  // 3. 关联费用记录
});
```

### 4. 审计追溯

**所有财务操作记录完整的审计日志**：

- 期初库存：记录在 InboundRecord，reason = "initial_stock"
- 盘点调整：关联 InventoryAdjustment
- 成本调整：记录在 CostAdjustment 表
- 费用分摊：记录在 ExpenseRecord

## 📊 数据库变更汇总

### 新增表

#### 1. CostAdjustment（成本调整表）

```prisma
model CostAdjustment {
  id               String    @id @default(uuid()) @db.Char(36)
  adjustmentNumber String    @unique @map("adjustment_number")
  productId        String    @map("product_id") @db.Char(36)
  variantId        String?   @map("variant_id") @db.Char(36)
  batchNumber      String?   @map("batch_number") @db.VarChar(100)
  beforeUnitCost   Float     @map("before_unit_cost")
  afterUnitCost    Float     @map("after_unit_cost")
  adjustmentAmount Float     @map("adjustment_amount")
  reason           String
  remarks          String?   @db.Text
  status           String    @default("draft") @db.VarChar(32)
  operatorId       String    @map("operator_id") @db.Char(36)
  approverId       String?   @map("approver_id") @db.Char(36)
  approvedAt       DateTime? @map("approved_at")
  createdAt        DateTime  @default(now()) @map("created_at")
  updatedAt        DateTime  @updatedAt @map("updated_at")

  product  Product @relation(fields: [productId], references: [id])
  operator User    @relation("CostAdjustmentOperator", fields: [operatorId], references: [id])
  approver User?   @relation("CostAdjustmentApprover", fields: [approverId], references: [id])

  @@index([productId])
  @@index([status])
  @@map("cost_adjustments")
}
```

### 修改表

#### 1. InventoryCountItem（新增字段）

```prisma
model InventoryCountItem {

  adjustment InventoryAdjustment? @relation(fields: [adjustmentId], references: [id])

  @@index([adjustmentId])
}
```

#### 2. InventoryCount（状态扩展）

```prisma
model InventoryCount {
  // ... 现有字段

  // 状态新增: adjusted
  status String @default("draft") @db.VarChar(32)
  // draft | in_progress | completed | adjusted | cancelled
}
```

#### 3. InboundRecord（扩展字段）

```prisma
model InboundRecord {
  // ... 现有字段

  reason String @default("purchase")
  // 枚举值: purchase | return | adjustment | transfer | initial_stock

  // 期初库存特殊字段
  isInitialStock Boolean @default(false) @map("is_initial_stock")
  costSource     String?  @map("cost_source") @db.VarChar(200)
  // 成本来源说明，例如: "2024年10月采购价" | "财务账面成本" | "供应商报价"
}
```

#### 4. Inventory（扩展瓷砖行业字段）

```prisma
model Inventory {
  // ... 现有字段

  // 瓷砖行业特殊字段
  colorCode      String?   @map("color_code") @db.VarChar(50)  // 色号
  batchNumber    String?   @map("batch_number") @db.VarChar(100)  // 批次号
  productionDate DateTime? @map("production_date")  // 生产日期

  // 唯一约束：产品+变体+色号+批次
  @@unique([productId, variantId, colorCode, batchNumber])
  @@index([productId, colorCode])
  @@index([batchNumber])
}
```

## 🔧 API接口汇总

### 期初库存接口（2个）

1. **POST** `/api/inventory/initial-stock/import` - 批量导入期初库存
2. **GET** `/api/inventory/initial-stock/template` - 下载导入模板

~~**已删除**: `GET /api/inventory/initial-stock/suggest-cost/:productId` - 成本建议算法（不适用于系统初次上线）~~

### 盘点差异处理接口（2个）

1. **POST** `/api/inventory/counts/:id/approve-adjustment` - 审批差异并调整
2. **GET** `/api/inventory/counts/:id/difference-report` - 获取差异报告

### 成本调整接口（3个）

1. **POST** `/api/inventory/cost-adjustments` - 创建成本调整申请
2. **PUT** `/api/inventory/cost-adjustments/:id/approve` - 审批成本调整
3. **GET** `/api/inventory/cost-adjustments` - 查询成本调整记录

### 费用分摊接口（2个）

1. **POST** `/api/finance/expenses/allocate-monthly` - 月末费用分摊
2. **GET** `/api/finance/expenses/allocation-report` - 费用分摊报告

### 财务报表接口（1个新增）

1. **GET** `/api/finance/reports/inventory-summary` - 进销存汇总表

## ⚠️ 风险提示

| 风险                  | 影响  | 概率  | 应对措施                                         |
| --------------------- | ----- | ----- | ------------------------------------------------ |
| 期初成本确定不准确    | 🔴 高 | 🟡 中 | 财务查账确定成本，财务主管审批，记录成本来源     |
| 批次色号管理不规范    | 🔴 高 | 🟡 中 | 强制要求录入批次和色号，系统校验唯一性           |
| 数据迁移失败          | 🔴 高 | 🟢 低 | 充分测试，准备回滚方案，选择业务低峰期           |
| 成本计算错误          | 🔴 高 | 🟢 低 | 单元测试覆盖，人工抽查验证，使用现有成熟算法     |
| Excel导入数据格式错误 | 🟡 中 | 🔴 高 | 提供标准模板，严格数据校验，详细错误提示         |
| 运费分摊计算不准确    | 🟡 中 | 🟡 中 | 提供运费分摊计算工具，财务审核                   |
| 性能问题              | 🟡 中 | 🟡 中 | 批量处理，异步任务，索引优化，限制单次导入1000条 |
| 用户操作错误          | 🟡 中 | 🟡 中 | 审批流程，操作日志，权限控制，重要操作二次确认   |
