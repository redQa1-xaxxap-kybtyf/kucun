# 入库表单空输入验证问题诊断报告

> **问题**: 用户不填写数字字段时，前端没有显示验证错误，请求直接发送到后端
>
> **诊断日期**: 2025-11-10
> **严重程度**: 🔴 高（影响用户体验）

---

## 📊 问题现象

### 当前行为（不符合预期）

1. 用户在数字字段（`inputQuantity`、`unitCost` 等）中**不输入任何内容**
2. 点击"提交"按钮
3. **前端没有显示验证错误**（字段没有红色高亮，没有错误信息）
4. 请求直接发送到后端
5. **后端返回验证错误**，用户才看到错误提示

### 预期行为

1. 用户在数字字段中不输入任何内容
2. 点击"提交"按钮
3. **前端立即显示验证错误**（字段红色高亮，显示 "数量必须是数字" 等错误信息）
4. **不发送请求到后端**
5. 用户在前端就能看到错误并修正

---

## 🔍 问题根源分析

### 根本原因：Zod Schema 的 `z.preprocess` 逻辑问题

**问题代码**（`lib/validations/inbound.ts` 第37-50行）:

```typescript
inputQuantity: z.preprocess(
  val => {
    if (val === undefined || val === null || val === '') {
      return undefined;  // ❌ 问题：返回 undefined
    }
    const num = typeof val === 'number' ? val : Number(val);
    return Number.isNaN(num) ? undefined : num;
  },
  z
    .number({ message: '数量必须是数字' })
    .min(1, { message: '数量必须大于等于1' })
    .max(999999, { message: '数量不能超过999999' })
    .int({ message: '数量必须是整数' })
),
```

**问题分析**:

1. **`z.preprocess` 的工作原理**:
   - `z.preprocess` 接收两个参数：
     - 第一个参数：预处理函数（转换输入值）
     - 第二个参数：Zod Schema（验证转换后的值）

2. **当前逻辑的问题**:
   - 当用户不填写字段时，`val` 为 `undefined`
   - 预处理函数返回 `undefined`
   - `z.number()` 接收到 `undefined`
   - **但是 `z.number()` 默认是可选的**，所以 `undefined` 通过了验证！

3. **为什么会通过验证**:

   ```typescript
   // Zod 的默认行为
   z.number(); // 等价于 z.number().optional()

   // 所以
   z.number().parse(undefined); // ✅ 通过验证，返回 undefined
   ```

4. **验证流程**:
   ```
   用户不填写字段
   → val = undefined
   → z.preprocess 返回 undefined
   → z.number() 接收 undefined
   → z.number() 认为 undefined 是有效的（因为默认可选）
   → ✅ 验证通过
   → 表单提交
   → 后端收到 undefined
   → 后端验证失败
   ```

---

## ✅ 修复方案

### 方案：在 Zod Schema 中明确标记为必填

**核心思路**:

- 保持 `z.preprocess` 的逻辑不变（处理空值）
- 在 `z.number()` 后面添加 `.refine()` 或使用 `z.number({ required_error: '...' })`
- 或者在预处理函数中抛出错误

**推荐方案1: 使用 `required_error`**（最简单）

```typescript
inputQuantity: z.preprocess(
  val => {
    if (val === undefined || val === null || val === '') {
      return undefined;
    }
    const num = typeof val === 'number' ? val : Number(val);
    return Number.isNaN(num) ? undefined : num;
  },
  z
    .number({
      required_error: '请填写入库数量',  // ✅ 添加必填错误信息
      invalid_type_error: '数量必须是数字',
    })
    .min(1, { message: '数量必须大于等于1' })
    .max(999999, { message: '数量不能超过999999' })
    .int({ message: '数量必须是整数' })
),
```

**推荐方案2: 在预处理函数中抛出错误**（更明确）

```typescript
inputQuantity: z.preprocess(
  val => {
    if (val === undefined || val === null || val === '') {
      throw new Error('请填写入库数量');  // ✅ 直接抛出错误
    }
    const num = typeof val === 'number' ? val : Number(val);
    if (Number.isNaN(num)) {
      throw new Error('数量必须是数字');
    }
    return num;
  },
  z
    .number()
    .min(1, { message: '数量必须大于等于1' })
    .max(999999, { message: '数量不能超过999999' })
    .int({ message: '数量必须是整数' })
),
```

**推荐方案3: 使用 `refine`**（最灵活）

```typescript
inputQuantity: z.preprocess(
  val => {
    if (val === undefined || val === null || val === '') {
      return undefined;
    }
    const num = typeof val === 'number' ? val : Number(val);
    return Number.isNaN(num) ? undefined : num;
  },
  z
    .number({ message: '数量必须是数字' })
    .refine(val => val !== undefined, { message: '请填写入库数量' })  // ✅ 添加必填验证
    .min(1, { message: '数量必须大于等于1' })
    .max(999999, { message: '数量不能超过999999' })
    .int({ message: '数量必须是整数' })
),
```
