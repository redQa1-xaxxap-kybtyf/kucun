### 6. N+1查询问题

**影响**: 性能下降,数据库负载增加,响应时间变慢

#### 已发现的N+1查询

**问题1: 循环中查询用户**

```typescript
// ❌ N+1查询 (scripts/check-orphaned-records.ts:30)
for (const record of inboundRecords) {
  const user = await prisma.user.findUnique({
    where: { id: record.userId },
  });
}

// ✅ 修复: 批量查询
const userIds = inboundRecords.map(r => r.userId);
const users = await prisma.user.findMany({
  where: { id: { in: userIds } },
});
const userMap = new Map(users.map(u => [u.id, u]));
```

**问题2: 订单列表查询产品信息**

```typescript
// ✅ 已优化 (lib/api/handlers/sales-orders/list.ts:178)
// 先查询订单,再批量查询产品
const productIds = orders.flatMap(order =>
  order.items.map(item => item.productId)
);
const products = await prisma.product.findMany({
  where: { id: { in: productIds } },
```

#### 优化建议

1. 使用 `include` 或 `select` 一次性加载关联数据
2. 使用 `_count` 替代 `include` 获取计数

### C.2 查询优化模式

#### 模式1: 使用\_count替代include

```typescript
// ❌ 慢查询 (加载所有关联数据)
const customers = await prisma.customer.findMany({
  include: {
    salesOrders: true, // 可能有数千条订单
    returnOrders: true,
  },
});

// ✅ 快速查询 (只获取计数)
const customers = await prisma.customer.findMany({
  select: {
    id: true,
    name: true,
    _count: {
      select: {
        salesOrders: true,
        returnOrders: true,
      },
    },
  },
});
```

#### 模式2: 批量查询避免N+1

```typescript
// ❌ N+1查询
const orders = await prisma.salesOrder.findMany();
for (const order of orders) {
  const customer = await prisma.customer.findUnique({
    where: { id: order.customerId },
  });
}

// ✅ 批量查询
const orders = await prisma.salesOrder.findMany({
  include: {
    customer: {
      select: { id: true, name: true },
    },
  },
});
```

#### 模式3: 使用游标分页

```typescript
// ❌ 偏移分页 (大偏移量性能差)
const page = 1000;
const limit = 20;
const orders = await prisma.salesOrder.findMany({
  skip: page * limit, // 跳过20000条记录!
  take: limit,
});

// ✅ 游标分页
const orders = await prisma.salesOrder.findMany({
  take: limit,
  cursor: lastOrderId ? { id: lastOrderId } : undefined,
  orderBy: { createdAt: 'desc' },
});
```
