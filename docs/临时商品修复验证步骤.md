**修改说明**:

- 增强了调货销售订单的验证逻辑

**修改后**:

```typescript
export function validateManualProductFields(
  items: SalesOrderItemFormData[],
  status: string,
  orderType?: 'NORMAL' | 'TRANSFER'
): boolean {
  // 1. 调货销售订单的手动商品必须有 productCode（包括草稿状态）
  if (orderType === 'TRANSFER') {
    for (const item of items) {
      if (item.isManualProduct) {
        const hasCode =
          typeof item.productCode === 'string' &&
          item.productCode.trim() !== '';

        if (!hasCode) {
          return false; // ✅ 没有 productCode 则验证失败
        }
      }
    }
  }

  // 2. 非草稿状态的订单，所有商品都需要验证必填字段
  if (status === 'draft') {
    return true;
  }
  // ...
}
```

-- 查看最新订单的临时商品关联
SELECT
  so.order_number,
  soi.product_code,
  soi.manual_product_name,
  soi.temporary_product_id,
  tp.code AS temp_code,
  tp.name AS temp_name
FROM sales_order_items soi
JOIN sales_orders so ON soi.sales_order_id = so.id
LEFT JOIN temporary_products tp ON soi.temporary_product_id = tp.id
WHERE soi.is_manual_product = 1

ORDER BY so.created_at DESC
LIMIT 5;

## 🐛 故障排查

### 问题 1: 验证逻辑未生效

**症状**: 仍然可以保存没有产品编码的手动商品

**排查步骤**:

1. 检查前端是否正确传递了 `orderType` 参数
2. 检查浏览器控制台是否有错误
3. 清除浏览器缓存并刷新页面

### 问题 2: 临时商品未创建

**症状**: 订单保存成功，但临时商品表中没有记录

**排查步骤**:

1. 检查订单项的 `isManualProduct` 字段是否为 `true`
2. 检查订单项的 `productCode` 字段是否有值
3. 检查订单的 `supplierId` 字段是否有值
4. 查看服务器日志是否有错误

### 问题 3: 临时商品未复用

**症状**: 创建了多个相同产品编码的临时商品

**排查步骤**:

1. 检查供应商是否相同（临时商品的唯一键是 `supplierId + code`）
2. 检查产品编码是否完全一致（包括大小写和空格）
3. 查看临时商品表的唯一索引是否正常

## 🎓 用户培训要点

1. **调货销售订单的手动商品必须填写产品编码**
   - 产品编码用于创建和复用临时商品
   - 即使是草稿状态也必须填写

2. **产品编码的作用**
   - 用于标识临时商品
   - 相同供应商 + 相同产品编码 = 同一个临时商品
   - 后续订单可以复用临时商品信息

3. **正确的操作流程**
   - 选择订单类型：调货销售
   - 选择供应商
   - 添加临时商品时填写产品编码
   - 填写其他商品信息
   - 保存订单
