# 核算口径合同（库存 / 销售 / 财务）

> 目标：把“同一笔业务在不同页面/不同链路/不同报表上数字一致”变成强约束，避免对账扯皮与经营决策误导。  
> 本文是**字段含义与计算路径**的唯一口径（需要代码与报表都遵守）。

---

## 0. 总原则（必须遵守）

1. **字段口径稳定**：同一字段名在任何地方含义一致；不允许“某处写入已包含、某处读取再加一次”。
2. **可解释与可追溯**：利润/应收/成本必须能解释“从哪些字段来、哪一步落库、何时可重算”。
3. **已确认 vs 待确认分离**：待确认收款只影响状态，不直接抵扣应收余额（否则会“提前结清”）。
4. **费用只允许计入一次**：公司承担费用要么进“成本（COGS）”，要么进“费用（Expense）”，报表必须过滤兜底，避免重复扣减。

---

## 1. 销售订单（SalesOrder）字段合同

### 1.1 订单金额口径（应收口径）

- `itemsAmount`：∑(订单行 `subtotal`)
- `additionalFees`：∑(订单费用项 `paidBy=customer` 的 `feeAmount`)
- `expenseAmount`：∑(订单费用项 `paidBy=company` 的 `feeAmount`)
- `roundingAdjustment`：下单抹零/加价（订单层），**不写入** `totalAmount`
- `totalAmount`：`itemsAmount + additionalFees`（**不包含** `roundingAdjustment`）
- `actualOrderDue`（概念值，不落库字段）：`totalAmount + roundingAdjustment`

对应实现（关键口径）：
- `lib/api/handlers/sales-orders/financials.ts`
- `lib/api/handlers/sales-orders/detail.ts`
- `lib/services/receivables-helpers.ts`

### 1.2 成本与利润口径（利润口径）

**统一利润公式**（系统标准）：
- `profitAmount = itemsAmount - costAmount`

其中：
- `costAmount`：订单级“已实现成本”口径，等于明细行 `costSubtotal` 的汇总（发货后以 FIFO 实耗回写；草稿/确认阶段可能为估算）
- `SalesOrderItem.costSubtotal`：行级“总成本”口径，包含：
  - 本地发货部分成本（FIFO/库存单位成本回退）
  - 调货部分成本（`unitCost * transferQuantity`）
  - 公司承担费用分摊（`allocatedExpense`）

注意：
- **公司承担费用默认计入成本**（以便利润统一按 `收入-成本` 计算），并在利润表/月报/年报的 `ExpenseRecord` 维度过滤 `relatedType='sales_order'` 避免重复扣减。

## 2. 销售模式（订单类型/履约模式）合同

### 2.1 A 普通销售（`orderType=NORMAL`）

库存动作：
- `confirmed`：预留库存（reservedQuantity += quantity）
- `shipped`：扣减库存并释放预留（quantity -= quantity；reservedQuantity -= min(quantity, reservedQuantity)），写出库记录（OutboundRecord）

成本来源：
- `shipped` 时以 FIFO 队列实耗为主；队列不可用时回退库存单位成本

验收要点：
- 发货后：`SalesOrder.costAmount == Σ SalesOrderItem.costSubtotal`
- 应收：`actualOrderDue == totalAmount + roundingAdjustment`

### 2.2 B 客户直发/纯调货（`orderType=TRANSFER + transferMode=SUPPLIER_ONLY`）

库存动作：
- 不预留、不扣减本地库存，不产生出库记录

成本来源：
- `unitCost` 为主（必须填写），行成本 ≈ `unitCost * quantity + allocatedExpense`

联动：
- `confirmed` 时可自动生成采购单/应付（以计算后的成本为准）

### 2.3 C 混合履约（`orderType=TRANSFER + transferMode=MIXED`）

库存动作：
- 本地部分（`localQuantity`）需要预留与发货扣减
- 调货部分（`transferQuantity`）不扣本地库存
- 强约束：`localQuantity + transferQuantity == quantity`

成本来源（行级合并口径）：
- 本地成本：FIFO 实耗（按 `localQuantity`）
- 调货成本：`unitCost * transferQuantity`（当 `transferQuantity > 0` 时 `unitCost` 必填）
- 行总成本：本地成本 + 调货成本 + `allocatedExpense`

风险提示：
- MIXED 是偏差高发模式：必须把“本地段/调货段”拆开算成本，再汇总落库；任何“只算一段”的实现都会导致利润结构性偏差。

## 3. 收款/应收（PaymentRecord / Receivables）合同

收款字段：
- `PaymentRecord.paymentAmount`：名义收款金额（账面）
- `PaymentRecord.actualPaymentAmount`：实际到账（现金/转账）
- `PaymentRecord.roundingAmount`：收款差额（找零/优惠/四舍五入等）

应收聚合规则（订单维度）：
- `paidAgainstOrder = Σ confirmed(actualPaymentAmount + roundingAmount)`
- `pendingAgainstOrder = Σ pending(actualPaymentAmount + roundingAmount)`（只用于状态判断）
- `remainingAmount = max(0, actualOrderDue - paidAgainstOrder)`

对应实现：
- `lib/services/receivables-helpers.ts`
- `lib/api/handlers/sales-orders/detail.ts`

---

## 4. 费用（ExpenseRecord）与报表口径

### 4.1 公司承担费用的落库与报表归集

- 订单费用项（feeItems）是业务输入；公司承担费用可自动生成 `ExpenseRecord(relatedType='sales_order')` 作为运营台账
- 但利润表/月报/年报按“利润口径”计算时：
  - 公司承担费用已分摊进 `SalesOrder.costAmount`
  - 因此报表侧需过滤掉 `ExpenseRecord.relatedType='sales_order'`，避免重复扣减

对应实现：
- `lib/services/report-helpers.ts`（P&L 口径的费用过滤）
- `lib/services/profit-loss-service.ts` / `lib/services/monthly-report-service.ts` / `lib/services/annual-report-service.ts`

---

## 5. 最小验收（DoD）清单（建议做成自动化回归）

每种模式各准备 1-2 单样例（含费用/抹零/部分本地部分调货），验收：

1. 创建/草稿更新/发货/收款/应收列表：`actualOrderDue` 一致
2. 发货后：`SalesOrder.costAmount == Σ SalesOrderItem.costSubtotal`
3. MIXED：本地发货扣减库存只针对 `localQuantity`，调货部分不影响本地库存
4. 利润表：不会对“销售订单公司承担费用”重复扣减

---

## 6. 数据审计（偏差定位）

当历史数据存在“旧口径写入 / 新口径读取”时，建议先跑审计脚本生成清单，再分批回填/修复：

- 脚本：`scripts/audit-sales-finance-calculations.ts`
- 运行：
  - `npm run audit:sales-finance`
  - `npm run audit:sales-finance -- 2025-01-01 2025-12-31 --fail`
- 输出：默认写入 `test-results/sales-finance-audit-*.{json,csv}`

若审计发现“订单头字段与明细/费用项不一致”，可使用安全回填脚本（默认 dry-run）：

- 脚本：`scripts/remediate-sales-finance-anomalies.ts`
- 运行：
  - `npm run remediate:sales-finance`
  - `npm run remediate:sales-finance -- --apply`

若需要对“采购-入库-库存-FIFO/往来账/应付”等跨模块做总览审计：

- 脚本：`scripts/audit-full.ts`
- 运行：`npm run audit:full`
