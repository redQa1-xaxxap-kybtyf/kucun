## 菜单层级说明

### 财务报表 (三级菜单)

- **一级**: 财务管理
- **二级**: 财务报表
- **三级**: 月度报表 / 年度报表 / 盈亏分析

### 库存盘点 (二级菜单)

- **二级**: 库存盘点

## 用户访问路径

### 财务报表功能

1. 点击侧边栏 "财务管理"
2. 展开 "财务报表" 子菜单
3. 选择具体报表类型:
   - 月度报表 → `/finance/reports/monthly`
   - 年度报表 → `/finance/reports/annual`
   - 盈亏分析 → `/finance/reports/profit-loss`

### 库存盘点功能

1. 点击侧边栏 "库存管理"
2. 选择 "库存盘点" → `/inventory/counts`

## 技术实现细节

### NavigationItem 类型

```typescript
interface NavigationItem {
  id: string; // 菜单项唯一标识 (kebab-case)
  title: string; // 菜单项标题 (中文)
  href: string; // 路由路径
  icon: LucideIcon; // 图标组件
  children?: NavigationItem[]; // 子菜单项 (可选)
  disabled?: boolean; // 是否禁用 (可选)
  requiredRoles?: UserRole[]; // 权限要求 (可选)
}
```

### 菜单 ID 命名规范

- 一级菜单: `{module}` (例如: `finance`, `inventory`)
- 二级菜单: `{module}-{feature}` (例如: `finance-reports`, `inventory-counts`)
- 三级菜单: `{module}-{feature}-{subfeature}` (例如: `finance-reports-monthly`)

### 路由路径规范

- 遵循 Next.js App Router 文件系统路由
- 路径与实际页面文件路径一致
- 例如: `/finance/reports/monthly` → `app/(dashboard)/finance/reports/monthly/page.tsx`

## 设计决策说明

### 为什么财务报表是三级菜单?

1. **功能归类**: 报表属于财务管理范畴,应归入财务管理菜单下
2. **扩展性**: 未来可能添加更多报表类型,三级菜单便于扩展
3. **用户习惯**: 财务人员习惯在财务管理模块下查找报表功能
4. **菜单平衡**: 避免一级菜单过多,保持菜单结构清晰

### 为什么库存盘点是二级菜单?

1. **功能归类**: 盘点是库存管理的核心功能之一
2. **访问频率**: 盘点功能使用频率较高,二级菜单便于快速访问
3. **菜单简洁**: 库存盘点下的子功能(任务列表、创建任务、统计分析)通过页面内导航实现

### 为什么不创建独立的"报表分析"一级菜单?

1. **当前阶段**: 目前只有财务报表,创建独立菜单显得单薄
2. **菜单数量**: 避免一级菜单过多,影响用户体验
3. **未来扩展**: 如果后续添加了库存报表、销售报表等,可以考虑重构为独立菜单
