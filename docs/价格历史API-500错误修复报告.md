## 📋 问题描述

### 问题现象

在销售订单新建页面，当用户选择客户后，前端自动调用价格历史 API 时出现 **500 Internal Server Error**。

### 错误详情

- **API 端点**: `GET /api/price-history/customer`
- **请求参数**: 
  - `customerId=75a92683-a47f-458b-bd74-bd9d7a7f31aa`
  - `priceType=SALES`
- **HTTP 状态码**: 500 (Internal Server Error)
- **完整 URL**: `http://localhost:3000/api/price-history/customer?customerId=75a92683-a47f-458b-bd74-bd9d7a7f31aa&priceType=SALES`

---

## 🔍 问题根源分析

### 1. Prisma Schema 缺少关系定义

**核心问题**：`CustomerProductPrice` 模型缺少与 `Customer` 和 `Product` 的关系定义。

#### 问题代码（修复前）

<augment_code_snippet path="prisma/schema.prisma" mode="EXCERPT">
````prisma
model CustomerProductPrice {
  id         String   @id @default(uuid()) @db.Char(36)
  customerId String   @map("customer_id") @db.Char(36)
  productId  String   @map("product_id") @db.Char(36)
  priceType  String   @map("price_type") @db.VarChar(64)
  unitPrice  Float    @map("unit_price")
  orderId    String?  @map("order_id") @db.Char(36)
  orderType  String?  @map("order_type") @db.VarChar(32)
  createdAt  DateTime @default(now()) @map("created_at")
  updatedAt  DateTime @updatedAt @map("updated_at")

  // ❌ 缺少关系定义！

  @@index([customerId, productId, priceType], map: "idx_customer_product_price_lookup")
  @@index([productId], map: "idx_customer_product_price_product")
  @@map("customer_product_prices")
}
````
</augment_code_snippet>

### 2. API 代码尝试使用不存在的关系

**API 代码**（`app/api/price-history/customer/route.ts`）：

<augment_code_snippet path="app/api/price-history/customer/route.ts" mode="EXCERPT">
````typescript
const prices = await prisma.customerProductPrice.findMany({
  where,
  orderBy: {
    createdAt: 'desc',
  },
  take: 10,
  include: {
    product: {  // ❌ 错误：product 关系不存在！
      select: {
        id: true,
        code: true,
        name: true,
        specification: true,
        unit: true,
      },
    },
  },
});
````
</augment_code_snippet>

### 3. 错误原因

当 Prisma 尝试执行 `include: { product: {...} }` 时，由于 Schema 中没有定义 `product` 关系，导致：
- **Prisma 无法生成正确的 SQL 查询**
- **运行时抛出错误**
- **API 返回 500 错误**

## ✅ 解决方案

### 修复步骤

#### 1. 在 `CustomerProductPrice` 模型中添加关系定义

<augment_code_snippet path="prisma/schema.prisma" mode="EXCERPT">
````prisma
model CustomerProductPrice {
  id         String   @id @default(uuid()) @db.Char(36)
  customerId String   @map("customer_id") @db.Char(36)
  productId  String   @map("product_id") @db.Char(36)
  priceType  String   @map("price_type") @db.VarChar(64)
  unitPrice  Float    @map("unit_price")
  orderId    String?  @map("order_id") @db.Char(36)
  orderType  String?  @map("order_type") @db.VarChar(32)
  createdAt  DateTime @default(now()) @map("created_at")
  updatedAt  DateTime @updatedAt @map("updated_at")

  // ✅ 添加关系定义
  customer Customer @relation(fields: [customerId], references: [id], onDelete: Cascade, onUpdate: Cascade)
  product  Product  @relation(fields: [productId], references: [id], onDelete: Cascade, onUpdate: Cascade)

  @@index([customerId, productId, priceType], map: "idx_customer_product_price_lookup")
  @@index([productId], map: "idx_customer_product_price_product")
  @@map("customer_product_prices")
}
````
</augment_code_snippet>

#### 4. 同时修复 `SupplierProductPrice` 模型

为了保持一致性，同时修复了供应商价格历史的关系定义：

<augment_code_snippet path="prisma/schema.prisma" mode="EXCERPT">
````prisma
model SupplierProductPrice {
  id         String   @id @default(uuid()) @db.Char(36)
  supplierId String   @map("supplier_id") @db.Char(36)
  productId  String   @map("product_id") @db.Char(36)
  unitPrice  Float    @map("unit_price")
  orderId    String?  @map("order_id") @db.Char(36)
  createdAt  DateTime @default(now()) @map("created_at")
  updatedAt  DateTime @updatedAt @map("updated_at")

  // ✅ 添加关系定义
  supplier Supplier @relation(fields: [supplierId], references: [id], onDelete: Cascade, onUpdate: Cascade)
  product  Product  @relation(fields: [productId], references: [id], onDelete: Cascade, onUpdate: Cascade)

  @@index([supplierId, productId], map: "idx_supplier_product_price_lookup")
  @@index([productId], map: "idx_supplier_product_price_product")
  @@map("supplier_product_prices")
}
````
</augment_code_snippet>

## 🎯 KISS、DRY、SOLID 原则应用

### KISS (Keep It Simple)
- ✅ 使用 Prisma 标准的关系定义语法
- ✅ 遵循 Prisma 官方最佳实践
- ✅ 不引入额外的复杂性

### DRY (Don't Repeat Yourself)
- ✅ 统一使用 Prisma 关系定义，避免手动 JOIN 查询
- ✅ 同时修复客户和供应商价格历史，保持一致性

### SOLID
- **单一职责 (SRP)**: 每个模型只负责自己的数据和关系
- **开放/封闭 (OCP)**: 添加关系不影响现有功能
- **依赖倒置 (DIP)**: API 依赖 Prisma 抽象，而不是直接操作数据库
