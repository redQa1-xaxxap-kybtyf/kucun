# 销售订单"确认发货"功能手动验证指南

> 用于验证缓存刷新修复（refetchQueries 替代 invalidateQueries）的手动测试指南

## 📋 测试目标

验证修复后的缓存刷新策略能够正确工作，确保用户操作后立即看到最新状态。

## 🔧 测试准备

### 1. 启动开发服务器
```bash
npm run dev
```
确保服务器运行在 `http://localhost:3000`

### 2. 准备测试数据

**需要至少 3 个"待发货"状态的销售订单**

#### 方法 1: 通过 UI 创建订单
1. 登录系统（用户名: `admin`, 密码: `admin123`）

3. 点击"新建订单"
4. 填写订单信息并保存
5. 将订单状态设置为"待发货"
6. 重复创建至少 3 个订单

#### 方法 2: 将已发货订单改回待发货

## 🐛 之前的 Bug 描述

**问题**: 当"待发货"列表中有多个订单时，点击第一个订单的"确认发货"按钮后，订单状态不会立即更新，需要手动刷新页面才能看到变化。

**原因**: 使用 `queryClient.invalidateQueries()` 只是标记查询为过期，不会立即重新获取数据。由于项目配置了 `staleTime: 30 * 1000`（30秒），在 30 秒内不会自动刷新。

**修复**: 将 `invalidateQueries` 改为 `refetchQueries`，并添加 `type: 'active'` 参数，强制立即重新获取数据，无论 `staleTime` 如何设置。

**修复代码**:
```typescript
// ❌ 之前
queryClient.invalidateQueries({ queryKey: salesOrderQueryKeys.lists() });

// ✅ 修复后
queryClient.refetchQueries({
  queryKey: salesOrderQueryKeys.lists(),
  type: 'active',
});
```

## 🔍 调试技巧

### 如果测试失败，检查以下内容：

1. **检查网络请求**
   - 打开开发者工具 > Network 标签
   - 查看是否有 API 请求失败
   - 查看响应数据是否正确

2. **检查控制台错误**
   - 打开开发者工具 > Console 标签
   - 查看是否有 JavaScript 错误

3. **检查 React Query DevTools**
   - 如果项目启用了 React Query DevTools
   - 查看查询状态和缓存数据

4. **检查代码**
   - 确认 `components/sales-orders/erp-sales-order-list.tsx` 中的修复代码
   - 确认使用的是 `refetchQueries` 而不是 `invalidateQueries`
   - 确认添加了 `type: 'active'` 参数
