# 测试数据种子脚本使用说明

## 📋 概述

本脚本为库存管理系统生成完整的测试数据，涵盖所有核心业务模块，便于开发和测试。

## 🎯 数据范围

### 生成的数据包括：

1. **用户管理** (4个用户)
   - 1个管理员账户
   - 3个销售员账户

2. **产品管理** (25个产品)
   - 5个产品分类（抛光砖、仿古砖、木纹砖、大理石砖、马赛克）
   - 每个分类5个产品
   - 包含完整的产品规格信息

3. **产品变体** (约20-30个)
   - 为部分产品创建色号变体
   - 每个产品2-4个色号

4. **客户管理** (20个客户)
   - 包含不同类型：批发商、装修公司、零售店、工程公司等
   - 不同信用等级和账期设置
   - 覆盖全国主要城市

5. **供应商管理** (15个供应商)
   - 主要瓷砖品牌供应商
   - 包含完整的联系信息

6. **库存记录** (约50-75条)
   - 每个产品1-3个批次
   - 随机库存数量和成本
   - 不同的存储位置

7. **入库记录** (40条)
   - 时间跨度：2024年7月-12月
   - 不同的入库原因（采购、退货、调拨等）

8. **销售订单** (50个)
   - 包含普通销售和调货销售
   - 不同状态：已确认、已发货、已完成
   - 每个订单2-5个产品明细

9. **收款记录** (约60-80条)
   - 为大部分订单创建收款记录
   - 支持分期收款
   - 不同的收款方式

10. **应付款记录** (25条)
    - 不同的付款状态
    - 不同的账期设置

11. **付款记录** (约20-30条)
    - 关联应付款记录
    - 支持分期付款

12. **厂家发货订单** (20个)
    - 不同的订单状态
    - 包含集装箱号等物流信息
    - 每个订单2-4个产品明细

13. **退货订单** (10个)
    - 不同的退货原因
    - 不同的处理方式（退款、换货）
    - 关联原销售订单

14. **退款记录** (8条)
    - 关联退货订单
    - 不同的退款方式

15. **系统日志** (100条)
    - 不同类型的操作日志
    - 覆盖各个业务模块

16. **系统设置** (3条)
    - 基础系统配置

## 🚀 使用方法

### 1. 首次运行（推荐）

```bash
# 运行 seed 脚本
npm run db:seed
```

### 2. 重置数据库并重新生成

```bash
# 清空数据库并重新运行所有迁移和 seed
npm run db:reset
```

### 3. 仅重新生成数据（保留表结构）

```bash
# 手动清空数据后运行 seed
npm run db:seed
```

## ⚠️ 注意事项

### 运行环境

- **仅在测试环境运行**：此脚本会生成大量测试数据，不要在生产环境运行
- **数据库要求**：确保数据库连接正常，DATABASE_URL 配置正确

### 数据特点

- **时间跨度**：所有数据的时间范围为 2024-07-01 至 2024-12-31
- **数据关联**：数据之间有完整的关联关系，符合业务逻辑
- **随机性**：每次运行生成的具体数值会有所不同，但数据结构和数量保持一致

### 幂等性

- 使用 `upsert` 操作确保可以重复运行
- 部分数据（如用户、分类）使用固定ID，避免重复创建
- 订单等业务数据每次运行会创建新记录

## 🐛 故障排除

### 问题1：运行失败，提示数据库连接错误

**解决方案**：检查 `.env.local` 文件中的 `DATABASE_URL` 配置是否正确

### 问题2：运行缓慢

**解决方案**：这是正常现象，生成大量数据需要时间（约1-3分钟）

### 问题3：部分数据创建失败

**解决方案**：

1. 检查数据库约束是否满足
2. 查看错误日志定位具体问题
3. 尝试运行 `npm run db:reset` 重新开始

### 问题4：重复运行导致数据重复

**解决方案**：

- 用户、分类等基础数据使用 `upsert`，不会重复
- 订单等业务数据会创建新记录，这是预期行为
- 如需完全重置，使用 `npm run db:reset`
