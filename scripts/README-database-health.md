# 数据库健康检查工具使用指南

## 📋 概述

本工具集提供全面的数据库健康检查和自动修复功能,确保数据完整性、一致性和关联关系的正确性。

## 🛠️ 工具列表

### 1. 数据库健康检查 (database-health-check.ts)

全面检查数据库的健康状况,包括:

- **孤儿数据检查**: 检查所有外键关联,找出引用了不存在记录的孤儿数据
- **数据重复检查**: 检查应该唯一但可能存在重复的记录
- **数据一致性检查**: 检查金额、状态等字段的合法性
- **关联关系完整性**: 检查订单与明细、支付与订单等关联关系

#### 使用方法

```bash
npx tsx scripts/database-health-check.ts
```

#### 检查项目

**1. 孤儿数据检查**
- ✅ 销售订单的客户关联
- ✅ 销售订单的用户关联
- ✅ 销售订单明细的订单关联
- ✅ 收款记录的客户关联
- ✅ 收款记录的订单关联
- ✅ 退款记录的订单关联
- ✅ 往来账单交易的账单关联
- ✅ 库存记录的产品关联

**2. 数据重复检查**
- ✅ 重复的订单号
- ✅ 重复的收款单号
- ✅ 重复的退款单号

**3. 数据一致性检查**
- ✅ 订单金额为负数
- ✅ 收款金额为负数
- ✅ 非法订单状态
- ✅ 非法收款状态
- ✅ 订单金额与明细不一致(包含费用项)
- ✅ 收款金额超过订单金额

**4. 关联关系完整性**
- ✅ 订单没有明细
- ✅ 已完成订单没有收款记录
- ✅ 账单实体是否存在

### 2. 数据库问题修复 (fix-database-issues.ts)

根据健康检查结果自动修复发现的问题。

#### 使用方法

```bash
# 先运行健康检查
npx tsx scripts/database-health-check.ts

# 如果发现问题,运行修复脚本
npx tsx scripts/fix-database-issues.ts

# 修复后再次检查
npx tsx scripts/database-health-check.ts
```

#### 修复功能

1. **修复收款状态问题**: 将非法状态修正为合法状态
2. **修复订单金额不一致**: 重新计算订单金额(明细+费用)
3. **删除孤儿数据**: 删除引用不存在记录的孤儿数据

### 3. 重复交易检查 (check-duplicate-transactions.js)

专门检查往来账单中的重复交易记录。

#### 使用方法

```bash
node scripts/check-duplicate-transactions.js
```

### 4. 重复交易清理 (clean-duplicate-transactions.js)

清理往来账单中的重复交易记录,保留最早创建的记录。

#### 使用方法

```bash
node scripts/clean-duplicate-transactions.js
```

### 5. 唯一约束验证 (verify-unique-constraint.js)

验证数据库唯一约束是否正确应用并生效。

#### 使用方法

```bash
node scripts/verify-unique-constraint.js
```

## 📊 问题严重级别

### ❌ Error (错误)
- 必须立即修复
- 会导致数据不一致或功能异常
- 例如: 孤儿数据、重复的唯一标识

### ⚠️ Warning (警告)
- 建议尽快修复
- 可能影响数据准确性
- 例如: 金额不一致、非法状态值

### ℹ️ Info (信息)
- 仅供参考
- 可能是正常业务场景
- 例如: 已完成订单没有收款记录(可能是现金交易)

## 🔄 推荐工作流程

### 日常检查

```bash
# 1. 运行健康检查
npx tsx scripts/database-health-check.ts

# 2. 如果发现问题,先备份数据库
npm run backup-db

# 3. 运行修复脚本
npx tsx scripts/fix-database-issues.ts

# 4. 再次检查确认修复成功
npx tsx scripts/database-health-check.ts

# 5. 测试相关功能
npm run dev
```

### 定期维护

建议每周运行一次健康检查,确保数据库状态良好。

```bash
# 添加到定时任务
# 每周一早上9点运行
0 9 * * 1 cd /path/to/project && npx tsx scripts/database-health-check.ts >> logs/health-check.log
```

## 🚨 注意事项

1. **备份优先**: 在运行修复脚本前,务必备份数据库
2. **测试环境**: 建议先在测试环境运行,确认无误后再在生产环境使用
3. **业务时间**: 避免在业务高峰期运行修复脚本
4. **日志保存**: 保存检查和修复的日志,便于追溯
5. **人工确认**: 对于重要数据的修复,建议人工确认后再执行

```typescript
  // ...

```

## 🔍 故障排查

### 问题: 检查脚本报错

**解决方案**:
1. 确认数据库连接正常
2. 检查 Prisma Client 是否最新: `npx prisma generate`
3. 查看错误日志,定位具体问题

### 问题: 修复后问题仍存在

**解决方案**:
1. 检查修复脚本的日志输出
2. 手动查询数据库确认数据状态
3. 可能需要自定义修复逻辑

### 问题: 性能问题

**解决方案**:
1. 对于大数据量,考虑分批处理
2. 添加适当的数据库索引
3. 在业务低峰期运行
